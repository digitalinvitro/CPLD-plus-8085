# tools/ — канонические инструменты сборки прошивок

Эта папка — МАСТЕР-ХРАНИЛИЩЕ инструментов сборки проекта CPLD-plus-8085.
Создана по просьбе владельца (11-13): чтобы ассемблер 8085 больше не
«переоткрывался заново» в каждой сессии, а жил в репозитории как единый
проверяемый инструмент.

## Состав

| Файл | Назначение |
| --- | --- |
| `asm85.py` | **Канонический ассемблер Intel 8085, v1.1** (единственный, всё собирает им) |
| `regression.py` | Регрессия: пересборка ВСЕХ прошивок репозитория байт-в-байт против закоммиченных `.hex` (27 образов) |

## asm85.py v1.1 — что это

Двухпроходный ассемблер на чистом Python (stdlib), `python3 tools/asm85.py`.
Это надмножество обеих линий ассемблеров, живших в проекте:

- **asm85** (копии в `beta/01_timer/rom`, `beta/lowsize/rom`,
  `beta/txuart/rom`, `beta/xstream/scripts`) — полная таблица 8085,
  выражения, IF/ELSE/ENDIF с вложением, отложенные EQU;
- **asm8085** (`beta/txuart/rom/txstress/asm8085.py`, исторический) —
  им собирались TXSTRESS и GFXSTREAM: метки на отдельной строке, строки
  DB в двойных кавычках, `.bin`-образ ПЗУ, T-листинг.

v1.1 объединяет всё, что нужно для сборки, и **доказано регрессией
27/27 образов байт-в-байт** (см. ниже). Уникальная особенность asm8085 —
листинг с T-состояниями — остаётся в его папке; для тактовых бюджетов
в проекте используются симуляторы (`beta/*/scripts/sim_*.py`).

## Использование

```bash
# базовая сборка (hex + листинг)
python3 tools/asm85.py beta/lowsize/rom/fw_mon.asm -o fw_mon.hex -l fw_mon.lst

# вариант прошивки ключами -D (перекрывают EQU файла)
python3 tools/asm85.py beta/xstream/xstream_v1.asm -o xstream_v1_hw.hex -D TMR_HW=1
python3 tools/asm85.py beta/txuart/rom/txstress/txstress_v11.asm -o txstress_v11_p04.hex -D TX_BOTH=0

# сразу образ ПЗУ 8 КБ (FF-заполнение; размер меняется --bin-size)
python3 tools/asm85.py beta/lowsize/rom/fw_mon.asm -o fw_mon.hex -b fw_mon.bin

# дизассемблировать готовый hex (проверка)
python3 tools/asm85.py --disasm xstream_v1.hex
```

## Синтаксис

- **Числа**: `1234h` (hex, может начинаться с буквы: `A000h`, `FFF8h`),
  `0x1234`, `123`, `123d`, `0110b`, `'A'`, `$` — текущий адрес.
- **Выражения**: `+ - * /` и скобки; символы регистронезависимы.
- **Метки**: `ИМЯ:` с инструкцией на той же строке ИЛИ метка на отдельной
  строке (адрес = текущий). Метки приводятся к верхнему регистру.
- **EQU**: обе формы — `ИМЯ EQU выражение` и `ИМЯ: EQU выражение`;
  ссылки вперёд разрешены (отложенное вычисление, цепочки). Чистый символ
  в выражении имеет приоритет над разбором чисел (метка `BDH` — не `0xBDh`).
- **Данные**: `DB 12h,'текст',0` и `DB "текст",0` (обе формы кавычек;
  строки кодируются в CP1251); `DW слово` (little-endian).
- **Директивы**: `ORG`, `EQU`, `DB`, `DW`, `IF выражение` / `ELSE` /
  `ENDIF` (вложение поддерживается), `END`.
- **Ключи**: `-o hex`, `-l lst` (CP1251), `-b bin` (FF-заполнение 8192,
  `--bin-size N`), `-D ИМЯ=ЗНАЧ` (несколько; перекрывает EQU файла с
  предупреждением в выводе), `--disasm hex`.
- **Кодировка исходника**: CP1251, фолбэк UTF-8 (так подхватываются
  UTF-8-источники gfxstream v2.x). Кириллица допустима ТОЛЬКО в комментариях
  (вне комментария — жёсткая ошибка). Таблица команд — полная 8085
  (включая RAL/RAR, SIM/RIM, условные CALL/RET).

## Регрессия (правило сопровождения)

```bash
python3 tools/regression.py        # 27 образов, вердикт PASS/FAIL
python3 tools/regression.py -v     # + вывод asm85 по каждой сборке
```

Покрывает **все** прошивки репозитория:

- `beta/01_timer/rom`: timer_test (тон/blink/n10), timer_test_uart,
  uart_echo_test, uart_sw_test, uart_echo_diag..diag6 — 12 образов;
- `beta/lowsize/rom`: fw_mon (полный/FAST), fw_test_disp (полный/FAST),
  fw_text_kbd (полный/FAST) — 6;
- `beta/txuart/rom`: uart_tx_test — 1;
- `beta/xstream`: xstream_v1 SW/HW (`TMR_HW=1`) — 2;
- `beta/txuart/rom/gfxstream`: v1, v2, v2.1, v2.2 — 4;
- `beta/txuart/rom/txstress`: v11 (полный/`TX_BOTH=0` p04) — 2.

**Единственное намеренное исключение**: `txstress_v10.hex` и
`txstress_v10_p04.hex` НЕ входят в регрессию — они построены до фикса бага
`size_of` (asm8085 v1.0, урок 11-10: непосредственная ALU считалась 1 байтом
вместо 2, адреса меток занижены на +13/+14). Это задокументированная УЛИКА
урока, она не воспроизводится никаким корректным ассемблером; проверено
побайтовой сверкой: расхождения — только адреса меток в непосредственных
операндах. Живая ветка — txstress v1.1 (в регрессии, 1-в-1).

**Правило**: любые правки `tools/asm85.py` — только после зелёного
`regression.py`; новые прошивки — добавить строку в `BUILDS`.

## Копии ассемблера по папкам — снапшоты

Копии `asm85.py`/`asm8085.py` в `beta/*/…` — СНАПШОТЫ того, чем были
собраны соответствующие закоммиченные hex (историческая достоверность).
Будущие сборки — всегда `tools/asm85.py`. Обновлять снапшоты «на всякий
случай» не нужно: эталон воспроизводимости — регрессия, а не копии.

## Уроки, вшитые в код asm85 v1.1

1. **Неактивные ветки IF не резолвят метки** (урок 11-12, xstream):
   строка в выключенной ветке IF/ELSE имеет `addr=None` и не участвует в
   присвоении адресов — иначе она затирала адрес метки, объявленной и в
   активной ветке (XSCHK:/XISR:).
2. **Метки на отдельной строке** — легальны (снимает ограничение клк10-69
   «метка только с инструкцией на одной строке»); старые исходники это
   не затрагивает (проверено регрессией).
3. **Размер DB со строкой** считается по символам строки, а не `len(ops)`
   — иначе метки после такой строки уезжали на `len-1` байт.
4. **Символ-приоритет в выражениях**: чистый операнд ищется в таблице
   символов ДО разбора чисел — метка `BDH` не превращается в `0xBDh`
   (поймано регрессией на gfxstream v2.x: JNZ BDH → 00BDh вместо 02D0h).
5. **Буквенное начало hex-литерала** (`A000h`, `FFF8h`) — легально
   (gfxstream; раньше требовалась первая цифра `0..9`).
6. **txstress_v10.hex не пересобирается намеренно** — улика урока 11-10
   о баге `size_of` (см. выше).

## История

- **v1.0** — линия asm85 (beta/01_timer → lowsize → xstream), линия
  asm8085 (txstress → gfxstream) — развивались параллельно по папкам.
- **v1.1 (11-13)** — слияние в `tools/asm85.py`: + метки на отдельной
  строке, + DB "…", + `-b/--bin`/`--bin-size`, + буквенные hex-литералы,
  + символ-приоритет в выражениях. Регрессия 27/27 байт-в-байт
  (все md5 совпали с задокументированными в коммитах: xstream
  4175b2e8/e5ed908c, gfxstream c2ae2d2e/3aacb4d0 и др.).
