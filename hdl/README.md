# hdl/ — HDL-проект XC95108 (retro_PCLD_board V2)

Исходники прошивки CPLD U1 (XC95108, PQFP-100) для платы retro_PCLD_board V2.
Проект собирается в Xilinx Web ISE 14.7 (Webpack) без сторонних библиотек.
Дизайн проверен фитом на реальном инструменте: отчёт `retro_pcld_top.rpt`
приложен в этой папке, фит успешен, 0 ошибок.

## Состав

| Файл | Что это |
|------|---------|
| `top_suart.v` | Verilog-1995, модуль `retro_pcld_top`: мост PC↔плата через soft-UART (транзитный режим), клок-дерево, POR, клавиатура, индикатор, зуммер |
| `top_suart.ucf` | 72 назначения ног (LOC) с комментариями в терминах платы (cpuNN, сегменты, строки/столбцы клавиатуры) |
| `retro_pcld_top.rpt` | Отчёт фиттера cpldfit (P.20131013) от 2026-10-21: успешный фит, распределение ресурсов, полные уравнения логики |
| `README.md` | Этот файл |

## ⚠ Кодировка: Windows-1251

Оба исходника (`top_suart.v`, `top_suart.ucf`) сохранены в однобайтовой
кодировке **Windows-1251** — это родная кодировка редактора Xilinx ISE на
русской Windows, кириллица в комментариях отображается корректно.

Следствие: предпросмотр этих файлов на github.com показывает кириллические
комментарии «кракозябрами» (GitHub ждёт UTF-8). Сам код при этом не страдает —
он чистый ASCII. Для просмотра на GitHub читайте этот README, а исходники
открывайте в ISE. При необходимости конвертация в UTF-8 делается одной
командой: `iconv -f CP1251 -t UTF-8 top_suart.v > out.v` (обратно —
`iconv -f UTF-8 -t CP1251`).

## Как собрать

1. Xilinx Web ISE 14.7: New Project → Family **XC9500 CPLDs** (XC95108 — это
   5-вольтовое семейство XC9500, НЕ CoolRunner), Device **XC95108**,
   Package **PQ100**, Speed **-15** (как в приложенном отчёте; флаг `-PQG100`
   на корпусе платы).
2. Добавить в проект `top_suart.v` и `top_suart.ucf`, назначить `top_suart.v`
   Top Module.
3. Опции синтеза/фита соответствуют отчёту: Optimization Method **DENSITY**,
   Slew Rate **FAST**, Power Mode **STD**, **Ground on Unused IOs = ON**
   (незадействованные ноги притянуты к земле — 9 свободных ног),
   Keep User Location Constraints **ON**.
4. Implement Design → программатор iMPACT: прошить полученный `.jed` по JTAG.

## Результаты фита (из retro_pcld_top.rpt)

Фит от 2026-10-21 21:55 — **с тайминг-констрейнтом на `clk`** (timing-driven):
фиттер реструктурировал логику ради скорости, поэтому ресурсы выросли против
безконстрейнтного прогона (было 100/108 MC, 246/540 PT, 202/216 FB-входов).
Дублирование штатное: буферные копии `D<7>_BUFR`, `D<6>_BUFR`, `D<0>_BUFR`
и локальные копии декода POR (`$OpTx$FX_DC$17xx`) по функциональным блокам.

| Ресурс | Использовано | Примечание |
|--------|--------------|------------|
| Макроячейки | 103/108 (95%) | исчерпаны FB1, FB2, FB4, FB5, FB6 (18/18); FB3 13/18 |
| Терм-продукты | 308/540 (57%) | запас есть |
| Входы функциональных блоков | 212/216 (98%) | впритык: FB2, FB3, FB5 по 36/36 |
| Регистры | 67/108 (62%) | пор-счётчик 14 бит, счётчики, защёлки, FSM |
| Ноги | 72/81 (89%) | свободны 9 ног: P74/75/76/78/79/81/95/96/98 |

Глобальные ресурсы: `clk` → **GCK3** (P29), дополнение `clk` → **GCK2**
(нужно negedge-триггерам XOR-пары делителя), GSR-сеть не используется —
сброс синхронный (`cpu_rst = RST | por_run`), нога P1 работает обычным входом.

## Предупреждения фиттера (все — некритичные)

1. **WARNING:Cpld — Unable to retrieve the path to the iSE Project Repository.**
   Проект запущен вне стандартного репозитория ISE; имя файла проекта взято по
   умолчанию. На результат не влияет.
2. **INFO:Cpld — Inferring BUFG constraint for signal 'clk' based upon the LOC
   constraint 'P29'.** Нога P29 — глобальная клоковая (GCK3), фиттер сам завёл
   такт на глобальную сеть. Явное объявление BUFG не требуется (INFO, не
   WARNING).
3. **WARNING:Cpld:897 — Unable to map all desired signals into function
   block, FB1. Buffering output signals D<7>, D<6>, D<0>.** FB1 переполнен по
   входам, фиттер вынес буферные копии `D<7>_BUFR`, `D<6>_BUFR`, `D<0>_BUFR`
   в FB4. Штатный приём cpldfit; при тайминг-констрейнте буферов стало три —
   фиттер дублирует логику ради скорости, функция не меняется.

## Тайминг

В самом cpldfit-отчёте результатов статического тайминга НЕТ (нет секций
slack/Fmax/«met») — фиттер лишь учитывает констрейнты при раскладке
(`Ignore Timing Specifications: OFF`). Проверка «мет/не мет» и худшие пути
выполняются отдельным шагом ISE: **Generate Post-Fit Timing Data** →
Post-Fit Static Timing Report (виден в Design Summary → Timing Constraints).

Ожидание по даташиту XC9500 (-15): цикл FF→FF через один терм ≈ 15 нс в
худшем случае против периода 40 нс (25 МГц на `clk`) — констрейнт должен
проходить с запасом ~2×; домен один, все триггеры на `clk` (X1 — только
выход, внутреннего клона нет). Оценка требует подтверждения отчётом
пост-фит тайминга.

## Частотная модель (v3)

Вход `clk` = 25,00 МГц (измерено, Task 29-d; GCK3). XOR-пара делит на 5:
X1 = 5,00 МГц с ровно 50% duty (100/100 нс), далее /2 → CPU 2,5 МГц,
T = 400 нс, квант 200 нс. POR = 2^14 квантов ≈ 3,28 мс.
Если на U7 окажется LTC6905-80 (штатные 20 МГц вместо измеренных 25),
тот же `.jed` даст X1 = 4,0 МГц / CPU 2,0 МГц — делитель CLK_DIV=5 зашит
жёстко; сверка маркировки U7 описана в SCHEMATIC.md §7.5.

## Верификация

Цепочка сверок «схема → нетлист → UCF → HDL → отчёт фиттера» замкнута:

индикатора (VT1–VT4 → CA0–CA3), PGND-математика (81 user I/O − 72 = 9

сверка отчёта фиттера↔UCF — 72/72 пина совпали (проверено на обоих фитах:
без констрейнта и с тайминг-констрейнтом).
