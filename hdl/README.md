# hdl/ — HDL-проект XC95108 (retro_PCLD_board V2)

Исходники прошивки CPLD U1 (XC95108, PQFP-100) для платы retro_PCLD_board V2.
Проект собирается в Xilinx Web ISE 14.7 (Webpack) без сторонних библиотек.
Дизайн проверен фитом на реальном инструменте: отчёт `retro_pcld_top.rpt`
приложен в этой папке, фит успешен, 0 ошибок.

> **СТАТУС: СТАБИЛЬНЫЙ BASELINE v3.2** (решение владельца, 2026-10-22).
> `top_suart.v` v3.2 — опорная точка: дальнейшие изменения делаются ОТ неё;
> эксперименты — в `beta/` (каждый со своим фитом). Железо на v3.2 проверено
> в работе. Финальный фит от 2026-10-22 («POR6»): 91/108 MC, 0 WARNING/ERROR
> размещения, 72/72 ноги по UCF, чек-лист PGND закрыт.

## ⚠ Кодировка: Windows-1251

Оба исходника (`top_suart.v`, `top_suart.ucf`) сохранены в однобайтовой
кодировке **Windows-1251** — это родная кодировка редактора Xilinx ISE на
русской Windows, кириллица в комментариях отображается корректно.

Следствие: предпросмотр этих файлов на github.com показывает кириллические
комментарии «кракозябрами» (GitHub ждёт UTF-8). Сам код при этом не страдает —
он чистый ASCII. Для просмотра на GitHub читайте этот README, а исходники
открывайте в ISE. При необходимости конвертация в UTF-8 делается одной
командой: `iconv -f CP1251 -t UTF-8 top_suart.v > out.v` (обратно —
`iconv -f UTF-8 -t CP1251`).

## Как собрать

1. Xilinx Web ISE 14.7: New Project → Family **XC9500 CPLDs** (XC95108 — это
   5-вольтовое семейство XC9500, НЕ CoolRunner), Device **XC95108**,
   Package **PQ100**, Speed **-15** (как в приложенном отчёте; флаг `-PQG100`
   на корпусе платы).
2. Добавить в проект `top_suart.v` и `top_suart.ucf`, назначить `top_suart.v`
   Top Module.
3. Опции синтеза/фита соответствуют отчёту: Optimization Method **DENSITY**,
   Slew Rate **FAST**, Power Mode **STD**, **Ground on Unused IOs = ON**
   (незадействованные ноги притянуты к земле — 9 свободных ног),
   Keep User Location Constraints **ON**.
4. Implement Design → программатор iMPACT: прошить полученный `.jed` по JTAG.

**Финальный фит v3.2 («POR6», 2026-10-22): Successful, 0 ошибок, 0 WARNING
размещения.** История ресурсов против первых фитов:

| Ресурс | v2 (первый фит) | v3 + тайминг-констрейнт | **v3.2 (финал)** |
|--------|-----------------|------------------------|------------------|
| Макроячейки | 100/108 (93%) | 103/108 (95%) | **91/108 (84%)** |
| Терм-продукты | 246/540 (46%) | 308/540 (57%) | **225/540 (42%)** |
| Входы функциональных блоков | 202/216 (94%) | 212/216 (98%) | **166/216 (77%)** |
| Регистры | 67/108 (62%) | 67/108 (62%) | **60/108 (56%)** |
| Буферы Cpld:897 | 1 | 3 | **0** |
| Ноги | 72/81 (89%) | 72/81 (89%) | 72/81 (89%) |

Экономия достигнута без потери функций (POR_W 14→6: −8 регистров;
регистровый `por_run` вместо комбинационного — снял все буферы; при этом
в дизайн ДОБАВЛЕНЫ защёлка `wb_ram_q` и регистровый `por_run`). Свободно
на будущее: 17 MC, 50 FB-входов, 315 PT. Исчерпаны: FB1 по входам (36/36)
и FB6 по макроячейкам (18/18).

Чек-лист UCF по финальному фиту закрыт полностью: 72/72 ноги совпали,
PGND = ровно {P74, P75, P76, P78, P79, P81, P95, P96, P98} (9 шт),
GSR-сеть не используется, `clk` → GCK3 (P29), дополнение `clk` → GCK2
(negedge-триггер `x1_n` XOR-пары).

Глобальные ресурсы: `clk` → **GCK3** (P29), дополнение `clk` → **GCK2**
(нужно negedge-триггерам XOR-пары делителя), GSR-сеть не используется —
сброс синхронный (`cpu_rst = RST | por_run`), нога P1 работает обычным входом.

## Тайминг

Пост-фит статический тайминг для v3.2 НЕ снимался: отчёт `Timing.twx` от
2026-10-21 относился к более раннему прогону (другая версия кода) и из
состава удалён. Ориентиры, почему 25 МГц достижимы и без него:

- историческая оценка по v3 (trce, verbose, 2026-10-21): худший цикл
  FF→FF 36 нс → Fmax 27,78 МГц > 25 МГц (запас +4 нс); полупериод
  XOR-пары 18 нс < 20 нс;
- в v3.2 структурные условия лучше: худший путь v3 `por_cnt→seg/dig`
  (36 нс) укорочен (счётчик POR 14→6 бит), все три буфера `D<*>_BUFR`
  убраны — логика плоская, без дублирования;
- решающий факт: железо на v3.2 работает (баннер, дисплей, клавиатура).

Формальный PASS при желании снимается так:
`trce -v 25 -o Timing.twx retro_pcld_top.ncd retro_pcld_top.pcf`.

## Частотная модель (v3)

Вход `clk` = 25,00 МГц (измерено, Task 29-d; GCK3). XOR-пара делит на 5:
X1 = 5,00 МГц с ровно 50% duty (100/100 нс), далее /2 → CPU 2,5 МГц,
T = 400 нс, квант 200 нс. POR = 2^6 квантов = 12,8 мкс (v3.1, POR_W 14→6:
даташит 8085A/1821ВМ85А требует минимум 3 такта CLK OUT = 1,2 мкс ПОСЛЕ
power-up при работающем клоке; CLK OUT = X1/2 тикает весь интервал сброса —
процессорные структуры готовы; счёт стартует только при живом clk 25 МГц;
−8 MC: 100/108 → ~92/108).
v3.2 (10-22, фит v3.1 — Placement Failed): `por_run` сделан регистром —
комб. NOR из 6 бит коллапсер вдавил в PT всех приёмников `cpu_rst`
(FB-входы 209/216, 12 BUFR-буферов = +12 MC, хелпер 8 PT/15 входов остался
без места); FF-выход не схлопывается в принципе. Ожидание: MC ~95,
буферы ~3 (как в v3), `por_run` — отдельный сигнал в отчёте.
Владелец подтвердил (2026-10-22): U7 = LTC6905HS5-80, частота 25,00 МГц
на входе CPLD подтверждена осциллографом и принята рабочей (под неё выдан
констрейнт). Расхождение с арифметикой «80/4 = 20 МГц» на HDL не влияет:
делитель CLK_DIV=5 зашит жёстко, при смене базовой частоты просто
масштабируются X1/CPU/POR (см. SCHEMATIC.md §7.5).

## Верификация

Цепочка сверок «схема → нетлист → UCF → HDL → отчёт фиттера» замкнута:
72/72 ноги, 75/75 цепей периметра, матрица клавиатуры 4×5, драйверы
индикатора (VT1–VT4 → CA0–CA3), PGND-математика (81 user I/O − 72 = 9
свободных). Сверка UCF↔нетлист — `SCHEMATIC.md` §5–§6 и `hardware/`;
сверка отчёта фиттера↔UCF — 72/72 пина совпали (проверено на обоих фитах:
без констрейнта и с тайминг-констрейнтом). Тайминговая цепочка замкнута:
констрейнт TS_clk (UCF) → timing-driven фит → фактические 36 нс < 40 нс
(Timing.twx), запас +4 нс по полному циклу и +2 нс по полупериоду XOR-пары.
