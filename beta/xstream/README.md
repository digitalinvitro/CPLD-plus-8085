# beta/xstream — ПРЕРЫВАНИЕ → ВЕСЬ ЭКРАН В UART (XSTREAM v1)

> **Идея владельца (ТЗ 11-12):** «8085, *прерываясь*, выдаёт в UART весь экран,
> потом идёт работать по своим делам в монитор fw_mon_ACdE.hex. Частоту
> прерывания надо рассчитать так, чтобы не нагружать ЦП больше 50% — от этого
> зависит FPS, но FPS не должен проваливаться и должен быть в интервале 20–25
> кадров/с. Если ЦП перегружен выдачей экрана — требование к FPS снижается,
> скажем до 10 FPS. Экран лежит по фиксированному адресу ОЗУ, например 0xB000.
> ПО клиента на ПК принимает поток и формирует экран в окне GUI».
>
> Это подпроект **xstream** — не путать с `beta/gfxstream` (демо-плеер с темпом
> от ПК): здесь темп задаёт ПЛАТА, экран — текстовый буфер ОЗУ, а монитор
> продолжает работать. Вся папка — прошивка, клиент, симулятор, расчёты.

**Статус (11-12):** прошивка v1 собрана, симулятор ПО РЕАЛЬНОМУ HEX —
**ВЕРДИКТ «ВСЁ ОК»** в обоих вариантах (SW-тик и HW-таймер): 0 отбросов TX,
мин. гэп 33T ≥ 31.25T, период 49.7–49.8 мс = 20.1 FPS, нагрузка ЦП 48.5%,
SEQ без пропусков, побайтовая сверка экрана, клавиши монитора работают.
Клиент `xstream_view.ps1` готов (BOM, 5.1-совместим; парсер сверен с симом
md5 1-в-1). Аппаратный вариант требует CPLD v24 — см. §7 (стена МЦ XC95108).

## 1. Архитектура режима

```
                    ┌───────────────────────── плата ─────────────────────────┐
 тик кадра ────────▶│  ISR/тик: выдать ВЕСЬ экран B000h..B7CFh в TX-UART      │
 (таймер v24 или    │  (2000 Б равномерно 35..49T/Б, слоты дисплея внутри)    │
  SW-накопитель)    │  → возврат: монитор fw_mon "ACdE" живёт дальше          │
                    └──────────────┬──────────────────────────────────────────┘
                                   ▼  1 000 000 бод 8N1 (CPLD TX-ядро v2.3, OUT 04h)
                    ┌──────────────┴──────────────────────────────────────────┐
                    │  xstream_view.ps1: A5 5A [SEQ] + 2000 Б → GUI 80x25     │
                    │  ресинк по магии, SEQ mod 256, FPS/гэпы/ресинки, -Log   │
                    └─────────────────────────────────────────────────────────┘
```

- **Экран** = текстовый буфер ОЗУ **B000h..B7CFh** (80×25 = 2000 Б, row-major).
  Любая программа (и сам монитор через режим E/C) может писать туда свой
  текст/графику — кадр уходит в ПК целиком, «как есть» (у клиента CP1251).
- **Монитор fw_mon «ACdE» не переписан, а ДОПОЛЕН**: вектор RST 7.5 (003Ch),
  init демо-экрана при холодном старте, тик кадра. Все режимы A/C/D/E/F1/F2,
  клавиатура, бип и дебаунс — работают как раньше.
- **Кто рисует в B000h:** при холодном старте прошивка выводит демо-экран
  (заголовок + живой счётчик SEQ в строке 22). Дальше буфер — полная
  собственность пользователя: пишешь текст по B000h → он появляется в окне ПК.

## 3. РАСЧЁТ режима (scripts/xstream_calc.py, подтверждено симом)

### 3.1 Исходные данные (железо, проверено на плате)

| Параметр | Значение | Откуда |
|---|---|---|
| CPU 1821ВМ85 (8085) | **3.125 МГц, T = 320 нс** | кольцо s0..s3 на 25 МГц (txuart v2.2/v2.3) |
| TX-UART CPLD | **1 000 000 бод 8N1**, байт = 10.0 мкс = **31.25T** | 25 МГц / 25, сетка CH340G точная |
| Линия | 100 000 Б/с; потолок подачи CPU **97 656 Б/с (97.7%)** | p04-прогон железно 97 887 Б/с |
| Запись в busy | **отбрасывается** ядром (кадр не портится) | топология v2.x; урок SPRINT 11-10-5 |

### 3.2 Кадр

- Экран 2000 Б + шапка `A5 5A [SEQ]` = **2003 Б/кадр**; чистый провод 20.03 мс.

### 3.3 Посылающий цикл — почему именно 35T/Б

TX-ядро принимает 1 Б за 31.25T; запись в занятое ядро **отбрасывается**, поэтому
пейсинг обязан быть **равномерным на КАЖДЫЙ байт** (урок SPRINT: пачки
развёртки 31T → каждый 2-й байт отбрасывается, даже при среднем 31T). Минимальная
петля из ОЗУ `MOV A,M (7) + OUT 04h (10) + INX H (6) = 23T` + пад из NOP с шагом 4T
→ 31T (8T пада) **меньше 31.25T — отбросы**; рабочий шаг = **35T/Б** (3 NOP).
Амортизация счётчика (DCR C + JNZ = 14T) на подгруппу 8 Б:

- подгруппа: 7×35T + 49T = **294T/8 Б = 36.75T/Б**;
- слот дисплея XDIG (147T с CALL) каждые 200 Б → **итого ≈ 37.6T/Б**;
- **посылка = 24.11 мс** (сим; расчёт 24.12 мс — сходится).

### 3.4 Нагрузка ЦП vs FPS (нагрузка = доля тактов, отданная выдаче кадра)

| FPS | период, мс | нагрузка ЦП | вердикт |
|---:|---:|---:|---|
| 10.0 | 100.0 | 24.1% | фолбэк ТЗ (не потребовался) |
| **20.0** | **50.0** | **48.2%** | **нижняя граница окна — ПРИНЯТО** |
| 20.1 | 49.8 | 48.5% | **рабочая точка v1 (сим: 49.75 мс)** |
| 21.0 | 47.6 | 50.6% | ЦП > 50% — не годится |
| 21.3 | 46.9 | 51.4% | (сетка 3 тика — не достижима при ≤50%) |
| 25.0 | 40.0 | 60.3% | не достижима при ≤50% |

**Вывод по ТЗ:** при 20–25 FPS и нагрузке ≤50% достижимое окно — **20.0–20.5 FPS**;
21 FPS и выше требуют >50% ЦП → по ТЗ владельца требование к FPS снижается до
**20 FPS** (нижняя граница окна 20–25, без провалов: сим держит 46.9–49.8 мс
даже при нажатых клавишах). Фолбэк 10 FPS = 24% ЦП — константой `XS_TH`/`TMR_N`,
не понадобился.

### 3.5 Период тика

- **SW-режим (TMR_HW=0, текущий CPLD):** тик = накопитель слотов скана монитора
  (`XS_TH=71` слотов × 0.361 мс) + посылка → **период 49.8 мс = 20.1 FPS**.
  Тик живёт в контексте монитора: поток идёт в меню, при наборе адреса/кода и
  во время дебаунса; **во время пользовательской программы (E) поток
  останавливается** — ЦП у программы.
- **HW-режим (TMR_HW=1, CPLD v24):** таймер CPLD → RST 7.5. Период =
  посылка + `XS_DIVN × N × 51.2 мкс`; **N=250, XS_DIVN=2 → 24.1 + 25.6 =
  49.7 мс = 20.1 FPS, 48.2%**. ISR выбивает из монитора и из пользовательской
  программы (пока та не DI) — поток НЕ останавливается никогда. Сим HW-варианта:
  49.98 мс, 0 отбросов, «ВСЁ ОК».

### 3.6 Дисплей и тон платы

Во время посылки регенерация 7-сегментника не замирает: слот XDIG каждые 200 Б
(2.4 мс) → полный цикл 4 разрядов ~9.6 мс (~104 Гц/разряд — без мерцания; в
паузе между кадрами монитор мерцает своими слотами скана ~0.36 мс). Тон бипа
продолжается: XDIG OR-ит SNDST в бит разряда. Индикатор платы приглушается на
время выдачи кадра — плата отдаёт канал экрану, это ожидаемое поведение режима.

## 4. Память и порты

| Область | Что |
|---|---|
| 0000h–7FFFh | ПЗУ (flash, запись железом отбрасывается); 0000h `JMP MAIN`; **003Ch вектор RST 7.5 = `JMP XISR`**; монитор с 0040h (вектор сместил SETTLE на 3 Б) |
| **B000h–B7CFh** | **ЭКРАН 80×25 (2000 Б)** — пользовательская область, xstream читает её каждый кадр |
| FFFAh–FFFCh | переменные xstream: `XSSEQ` (SEQ mod 256), `XSPASS` (SW-накопитель), `XSDIV` (HW-делитель); выше PREVST (FFF9h), стек (FFE7h↓) не доходит |
| FFE8h–FFF9h | переменные монитора (без изменений) |
| 8000h–B7CEh | остальное ОЗУ — свободно для программ |
| 00h/01h/02h/03h | сегменты / разряды+SND / колонки / ряды (монитор) |
| 04h / 05h | TXDATA / TXRDY (ядро TX v2.3) |
| 06h | **в v24 — загрузка N таймера** (на v2.3 записи игнорируются — прошивка безопасна на обоих образах CPLD) |

## 5. Формат провода (2003 Б/кадр)

```
A5 5A [SEQ] [2000 Б экрана: строка 0 (80 Б), строка 1, ... строка 24]
```
- SEQ++ mod 256 в каждом кадре — клиент считает гэпы (пропуски/сброс платы).
- Ресинк по A5 5A: мусор до магии отбрасывается (счётчик ресинков).
- Хвост без добивки — кадр распознаётся по счёту 2000 Б после шапки.

## 6. Запуск

**Плата (SW-режим, текущий CPLD txuart v2.3):** прошить `xstream_v1.hex`
во flash с offset 0 (вместо монитора — монитор внутри), терминал на 1 000 000
8N1 закрыть.

**ПК:**
```powershell
.\xstream_view.ps1 -Port COM13                    # окно 80x25, метрики в статусе
.\xstream_view.ps1 -Port COM13 -Log xs_log.csv    # + CSV: utc,kind,seq,dt_ms,...
.\xstream_view.ps1 -SelfTest                      # 4/4 без порта: склейка чтения,
                                                  # мусор→ресинк, гэп SEQ, CP1251
```
Статусная строка: FPS (EMA), период мс, кадров, SEQ-гэпы, ресинки, КБ, время.
Критерий приёмки: **FPS 20±0.5 стабильно, SEQ-гэпы 0** (кроме сброса платы),
ресинк-байтов 0 в стационаре, экран в окне = демо-экран платы, счётчик SEQ
в строке 22 ticking.

## 7. Железо: таймер → RST 7.5 (CPLD v24) и стена МЦ XC95108

Для «настоящего» прерывания нужен остров таймера в CPLD (база таймерной линии —
`beta/01_timer`, v3.3b3: тик 51.2 мкс, загрузка N через порт, стоп-в-нуле,
ре-арм из ISR, вектор 003Ch). Но:

| Сборка | МЦ | Источник |
|---|---|---|
| база v3.9.8-clear | 94/108 | фит 11-7 |
| **txuart v2.3 (текущая)** | **103/108** (вх.ФБ 211/216 = 98%) | фит 11-9 7:26PM |
| txuart + остров таймера | **~121/108** — НЕ ЛОЖИТСЯ | прескалер 8 МЦ (txm_cnt в базе v2.3 удалён) + счётчик 8 + строб 1 + P75 1 |

Вывод: на XC95108 совмещение «1М TX-ядро + таймер» невозможно (это же
подтверждает обе линии по отдельности: txuart-103 и таймер-v3.3b3-103 на
базе v3.2). Варианты: (а) XC95144 — недоступна; (б) v24 с зачисткой — отдельная
работа по смете. Поэтому v1 работает в SW-режиме на текущем образе CPLD, а
прошивка уже содержит полный HW-путь: вектор 003Ch, ISR с делителем и ре-армом
(`OUT 06h`), маску SIM — при будущем фите v24 достаточно `-D TMR_HW=1`.
Расчёты HW-режима (§3.5) и сим таймера v24 (инъекция прерываний по `OUT 06h`)
уже выполнены.

## 8. Уроки этой линии (для DEVLOG)

1. **asm85: метка на строке `IF`** получает адрес… никакой — резолв уходил в
   0x0000 (`CALL XSCHK` = `CALL 0000` → цикл перезагрузок 30 мс). Метки — на
   всегда-активных строках; фикс резолва в `scripts/asm85.py` (неактивные
   ветки не участвуют), регрессия fw_mon/fw_mon_fast — байт-в-байт.
2. **Равномерность пейсинга важнее среднего**: развёртка 4 Б с общим падом
   давала гэпы 23T (отбросы) при среднем 32.5T. Гэп КАЖДОЙ записи ≥ 31.25T —
   как в p04.
3. **Счётчик группы — часть бюджета тактов**: DCR C+JNZ добавлял 3.5T/Б сверх
   модели → посылка 25.8 мс вместо 24.2. Амортизировать на подгруппу 8 Б.
4. **Сим: CMP не меняет A; STAX/LDAX — полная пара; MOV r,M — из памяти** —
   три классических бага интерпретатора, пойманы побайтовыми сверками.
5. **Период HW = посылка + XS_DIVN × N тиков** (не (DIVN−1)!): делитель
   инкрементируется в ISR ПОСЛЕ ре-арма; делитель 3 дал 61 мс (сим поймал до
   железа).
