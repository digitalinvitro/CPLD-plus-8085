## Карта портов (дополнение к §5 базовой)

| Порт | R/W | Биты | Функция |
|---|---|---|---|
| `04h` | OUT | D7..D0 | **TXDATA**: старт кадра. Запись при TXRDY=0 — байт **тихо отбрасывается** (кадр не портится) |
| `05h` | IN | A1 | **TXRDY** (1 = ядро в idle, кадр можно стартовать) |
| `05h` | IN | A0, A7..A2 | 0 (резерв) |
| `04h` | IN | — | **НЕ определён** (RX нет; уходит в bus_reg, не использовать) |

## Архитектура ядра (п.26-п.28 шапки RTL) — 20 МЦ

```
shreg[8:0]    9 МЦ — {данные/выход}: [0]->TX (IO-MC P39, INIT=1 — idle '1');
              загрузка ld_tx_q: {A[7:0], 1'b0} с живых A-пинов (CPU держит
              данные до подъёма WRn — запас ≥ 20 тиков); сдвиги вправо с
              инжекцией '1' -> после 9 сдвигов shreg САМ в все-'1' (idle по
              построению, как shreg 9'h1FF txclient; параллельных загрузок idle НЕТ);
bit_cnt[3:0]  4 МЦ — 0..9 (0=idle, 1..9 — сдвиги кадра);
baud_cnt[3:0] 4 МЦ — mod-16 СВОБОДНЫМ ходом: D = bc+1, wrap натуральный —
              «счётчиковый» делитель; jam <= 1 при загрузке;
tx_run        1 МЦ — идёт передача (TXRDY = !tx_run);
adv_q         1 МЦ — регистровый хелпер тика сдвига (п.21 v8: декод не
              копируется в D-функции битов shreg);
ld_tx_q       1 МЦ — РЕГИСТРОВЫЙ строб загрузки (п.28, см. ниже).
```

**п.28 — главное отличие от hwuart v4.0.x (лекарство от стены вх.ФБ фитов
11-4/11-5):** там декод `io_wr_tx` (11 литералов) грузил shreg НАПРЯМУЮ →
16 потребителей, +42 вх.ФБ, 213/216 (99%), Placement Failed ×3. Здесь
`io_wr_tx` (12 литералов: state×3, 04h×3, IOM, !WRn, !tx_run, !ld_tx_q,
!por_run) имеет **ЕДИНСТВЕННОГО потребителя** (`ld_tx_q.D`); загрузка — на
тик позже строба (данные живы); D-функция бита shreg = 3 ПТ/~5 вх
{ld_tx_q, A[k], adv_q, shreg[k+1], shreg[k]} → все 9 бит ложатся в ОДИН ФБ
(~27 вх ≤ 36).

**Тайминг кадра (п.29):** загрузка → старт-бит '0' с этого такта; jam
`baud_cnt <= 1` → первый сдвиг (adv_q) ровно на T+16 (лаг adv_q 1 такт; jam 0
дал бы 17 — урок v8/hwuart) → старт **ровно 16 тиков**, ВСЕ переходы на сетке
16 тиков; инжекция '1' — на 9-м сдвиге стоп сам в [0]; кадр закрывается на
10-м тике ядра (TXRDY ~15-й тик стопа) — при непрерывном поллинге фактический
стоп у ПК ≥ 1 полного бита.

## Контракт (для прошивки)

1. `OUT 04h` — только при TXRDY=1 (поллинг `IN 05h` бит 1; прецедент hwuart:
   период опроса ≪ бита, потерь нет).
2. Запись при активной передаче — байт ТИХО ОТБРАСЫВАЕТСЯ (кадр не портится).
3. Окно POR: запись 04h отбрасывается (!por_run в стробе) — floated-шина
   CPU в сбросе не рождает кадр-мусор (класс v8/v3.9.3 п.18).
4. ПК-сторона: терминал/приёмник на **1 000 000 8N1** (v2.3; точная сетка
   CH340G 48М/48. v2.2 просил 1 562 500 — CH340G такое не умеет: драйвер
   молча ставил 1 500 000, +4,17 % = мусор, урок 11-9).

## Чек-лист фита (владельцу, после прогона ISE)

Опции: как у фит-3 hwuart/успешной линии — **Input Limit 16, Pterm 18,
Exhaustive OFF, DENSITY**; если ERROR 891/892 — IL 28, далее Exhaustive ON.

1. `Fitting Status: Successful`, 0 ERROR; WARNING Cpld:897 ≤ 1-2 (класс D<7>);
   **WARNING:Xst:1780 в логе синтеза БЫТЬ НЕ ДОЛЖНО** (точка приёмки
   v398_clear: в RTL нет мёртвых идентификаторов — проверено check_v1).
2. Ресурсы (прогноз п.30 шапки): МЦ **102-104**/108 (85 − 3 транзит + 20 ядро
   + 1-2 хелпера $OpTx), вх.ФБ **~190-205**/216, ПТ **~250-280**/540, рег **71**,
   ноги **72/81** (пины = базе, UCF = hdl/top_suart.ucf по LOC 1-в-1).
3. **GSR**: «Signal 'RST' mapped onto global set/reset net GSR.» + «GSR : 1»;
   ядро TXUART + FSM/шина — CLR/SET=RST; por_sh×8/por_run/делитель — вне GSR.

## Прошивка ПЗУ для железной проверки TX — `rom/uart_tx_test`

Задача владельца «готовь прошивку в ПЗУ для проверки работы UART на
передачу». Прошивка автономная (не монитор): после POR шлёт в
аппаратный TXUART строку и мультиплексирует индикатор.

**Что делает:**

- Раз в ~200 мс: строка **`TXUART v2.2 OK N=xx`** + CR LF, xx — счётчик
  строк (hex, mod 256). Каждый байт — строго после поллинга **TXRDY=1**
  (`IN 05h, ANI 02h` — контракт п.1; запись при busy тихо отбрасывается
  ядром, поэтому поллинг обязателен).
- Индикатор: мультиплекс 1 мс/разряд (250 Гц): DIG3=`t` (тест идёт),
  DIG2/DIG1=`-`, DIG0 = млад. нибл счётчика. OUT 00h = сегменты,
  OUT 01h = разряды (A4 = SND — держится 0, звук молчит).
- Прерывания запрещены (INT-линии заземлены PGND), стек в ОЗУ на
  0E000h, CPU 3,125 МГц (T = 320 нс).

**Тайминги (померены симуляцией по реальному HEX):** срез 1 мс =
3117 T = 997,4 мкс (−0,3 %); период строк 626 870 T = 200,6 мс; кадр
UART 6,4 мкс = 20 T; период опроса TXRDY ~27–90 T — TXRDY уровень,
промаха нет; первый байт уходит при TXRDY=1 (ядро idle с POR).

**Проверки симуляции `rom/sim_uart_tx_test.py` (10/10 ПАСС,
672 мс CPU = 2,1 млн T):** C0 первый байт при TXRDY=1; C1 все OUT 04h
при TXRDY=1 (84/84, нарушений 0); C2 поток 1-в-1 «TXUART v2.2 OK
N=00..03» ×4, хвост 0 (байты не теряются/не дублируются); C3 период
строк 626 870 T; C4 срез 3117 T; C5 фазы 01→02→04→08 по 3117 T, глифы
DIG0=HTAB[C&0F]/'-'/='t', призрак seg→dig < 15 T; C6 бит A4 (SND) всех
записей порта 01h = 0; C7 нет HLT/зависаний.

**Сборка и проверка:**

```
python3 beta/01_timer/rom/asm85.py beta/txuart/rom/uart_tx_test.asm \
        -o beta/txuart/rom/uart_tx_test.hex -l beta/txuart/rom/uart_tx_test.lst
python3 beta/txuart/rom/sim_uart_tx_test.py     # из любого места
```

(в `rom/` лежит копия asm85.py — можно собирать из каталога;
исходник CP1251, канон проекта; `_utf8`-двойник рядом.)

**Что ожидать на железе** (после шунта H1 + прошивки CPLD + прошивки
ПЗУ): терминал 1 562 500 8N1 — ~5 строк/с, N растёт на 1; индикатор:
`t.-N`. Если строк НЕТ, но индикатор жив — TX-путь (CPLD P39 → CH340G
RXD) или терминал; если нет и индикатора — CPU/шина/питание (индикатор
после сброса должен светить «8.8.8.8.» до первого OUT 00h — прошивка
берёт дисплей на себя за первые миллисекунды).

**Примечание:** уроки первой сборки (исправлены в v2 финала): (1)
таблицы глифов/масок положены на границы страниц 0200h/0300h — страничная
адресация `MVI H,страница` + `MOV L,индекс`; (2) PUTH шлёт в UART
ASCII-символ ('0'..'9','A'..'F'), а не глиф индикатора; HTAB — только
для дисплея. Симулятор (по прецеденту lowsize/verify_fw.py) выловил
оба до железа + собственные баги симулятора: PUSH 8085 — pre-decrement
SP, rp-пары (lo,hi).

### Диагноз: hex v1.0 исполнялся КОРРУПТИРОВАННЫМ — виноват ассемблер, не плата

в 0x0086, а метка FLC реально стояла в 0x0093. Причина — `size_of()` в
`rom/txstress/asm8085.py` не знал двухбайтовых непосредственных ALU
(**ANI/ADI/ACI/SUI/SBI/XRI/ORI/CPI**): проход 1 считал их однобайтовыми,
проход 2 эмиссил два байта → все метки ПОСЛЕ первого ANI уезжали: +1 к
PB2D (один ANI гейта), **+13 к FLC** (гейт + 4 цифры × ANI+ADI+ACI), **+14
ко всему дальше** (ещё CPI). В прошитом v1.0.hex:

- `LXI H,M_BAN` грузил **M_BAN−14** → PBAN печатал байты КОДА до ближайшего

  вместо него 13 мусорных байтов;
- лендмарки не печатались никогда (гейт `JNZ FLC` валился в середину
  цифро-печатного кода);
- **после FLOOD ЦП уходил в дикий цикл**: прыжки `JZ FDONE`/`JNZ SPIN`
  вели в чужой код, и программа навсегда печатала байт **53h ('S')** в темпе
  цикла печати 54T/байт ≈ 58.2 КБ/с.

### ФИКС ассемблера + пересборка TXSTRESS v1.1

`size_of()` дополнен списком непосредственных ALU (2 байта). Повторная
сборка: все метки 1-в-1 (`LXI H,M_BAN` → 0138h = M_BAN; `JNZ FLC` → 0093h
= FLC; …). Изменения исходника v1.1:

1. **Баннер «TXSTRESS v1.1»** (PC-сторона принимает оба баннера по regex).
2. **Чин гейта лендмарков** (независимо от бага ассемблера, поймано по
   столу): в v1.0 гейт смотрел СТАРШИЙ байт счётчика (`MOV A,D; ANI 01Fh`)
   — весь первый килоблок DE=0000h..00FFh даёт D=00 → лендмарк печатался бы
   КАЖДЫЙ блок (256 «B=00xx» вместо 7). Теперь `MOV A,E; ANI 01Fh; JNZ FLC;
   MOV A,E; ORA A; JZ FLC` → кратен 32 блокам И E≠0 → **ровно 7 лендмарков
   B=0020..00E0**, 1-в-1 с ожиданиями uart_speed и эталон-генератором.
3. **Токен синхронизации**: лендмарк = `B=xxxx TXSTRESS\r\n` — поток сам
   называет себя каждые 8 КБ (~107 мс): если баннер цикла не пойман,
   PC-сторона доказуемо видит, что исполняется TXSTRESS, и где она внутри
   FLOOD.
4. **POR-пауза 126 → 503 мс** (`LXI D,0000h`): запас открыть терминал/скрипт
   до первого баннера.
5. **Пауза ~19.7 мс тишины** перед баннером каждого цикла (`LXI D,0A00h`):
   баннер выходит из чистого idle; хвост «BURST OK → баннер» остаётся пустым
   по байтам.

Темпы фаз НЕ тронуты (FLOOD 42T, SPRINT 31T, BURST 14.875T); head = 379
байт (0000h–017Ah), p04 = 353 байта.
