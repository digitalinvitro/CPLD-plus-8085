# beta/txuart — исключительно аппаратный передатчик UART («счётчиковый» бод-рейтинг)

> **АКТУАЛЬНО (11-8веч): v2.0 НА БАЗЕ v3.9.8-clear** (директива владельца
> «Берем дизайн beta\lowsize 398_clear и переделываем txuart на основе него»)
> — кольцо r0..r6 вернулось в нетлист, ядро на clk25 (бод ровно 1 562 500,
> фикс v1.1 mod-32 не нужен), цель XC95144-15PQ100C. Полное описание и статус
> — в конце файла. Ниже — история v1.0 (база v3.9.3).

**Директива владельца (11-8):** «Хорошо давай попробуем организовать исключительно
аппаратный трансмиттер UART, на удобный для счетчиков делителей бод рейтинг,
реализации посмотри в txclient, проект разместим в beta\txuart».

**База:** `beta/lowsize/top_suart_por6_v393.v` (v3.9.3, фит 11-2 9:54PM **прошит
и работает**: 85/108 МЦ, 195/540 ПТ, 171/216 вх.ФБ, 54 триггера, 72/81 ноги,
сброс → GSR). **Правило линии:** база бит-в-бит, ядро ложится ТОЛЬКО на свободный
ресурс + ресурс выпиленных soft-UART-транзитов. Дисплей/клавиатура/FSM/шина/
writeback/POR — не тронуты (контрольные строки — `scripts/check_v1.py`).

## Спека

| Параметр | Значение | Основание |
|---|---|---|
| Что | **TX-only**: только передатчик, RX нет | директива «исключительно аппаратный трансмиттер»; приём — программный (SID = RX, RIM 20h — как в lowsize) |
| Скорость | **1 562 500 бод 8N1** (25 МГц / 2⁴) | «удобный для счетчиков делителей бод рейтинг»: делитель — свободный двоичный mod-16, wrap **натуральный** (1111→0000), декода терминального счёта и сбросовой логики в D-функциях счётчика НЕТ; BAUD_DIV=16 — из списка альтернатив шапки txclient v8 («16 → 1 562 500, wrap без декода»); CH340G до 2 Мбит (проверен владельцем на 1,92 М = 25/13) |
| Доступ CPU | **IO-порты**: `OUT 04h` = TXDATA, `IN 05h` = статус | декод по `addr_latch[2:0]` (класс hwuart); 04h-07h — резерв от удалённого UART (Task 69) |
| Статус | `IN 05h` = {000000, **TXRDY**, 0}: бит A1 = `!tx_run` | позиция бита — совместимость с hwuart v4.0.x (та же прошивка поллинга); чтение — механизмом KBROW (A-пины, `rd_drive`) |
| Кадр | 8N1, 10 бит, стоп ≥ 1 бита (бесконечный idle) | стандарт терминалов; приёмник терпит длинный стоп |
| Транзиты v3.9.3 | **TX-транзит выпилен** (sod_q/tx_pass/tx_q/cpu_rst, −3 МЦ); **SID = RX сохранён** (0 доп. МЦ; старый RIM-ввод и diag6 живут); **SOD (P72) — вход-наблюдатель keep** (выход CPU заземлять нельзя) | класс hwuart v4.0.x |
| Сброс | ядро в GSR-домене: shreg — SET-ветка (INIT=1FF, idle '1' до всякого клока), счётчики/tx_run — CLR; пор-цепь/делитель — вне GSR | класс v3.9.3 п.18 / hwuart п.26 |

## Карта портов (дополнение к §5 базовой)

| Порт | R/W | Биты | Функция |
|---|---|---|---|
| `04h` | OUT | D7..D0 | **TXDATA**: старт кадра. Запись при TXRDY=0 — байт **тихо отбрасывается** (кадр не портится) |
| `05h` | IN | A1 | **TXRDY** (1 = ядро в idle, кадр можно стартовать) |
| `05h` | IN | A0, A7..A2 | 0 (резерв) |
| `04h` | IN | — | **НЕ определён** (RX нет; уходит в bus_reg, не использовать) |

## Архитектура ядра (п.26-п.28 шапки RTL) — 20 МЦ

```
shreg[8:0]    9 МЦ — {данные/выход}: [0]->TX (IO-MC P39, INIT=1 — idle '1');
              загрузка ld_tx_q: {A[7:0], 1'b0} с живых A-пинов (CPU держит
              данные до подъёма WRn — запас ≥ 20 тиков); сдвиги вправо с
              инжекцией '1' -> после 9 сдвигов shreg САМ в все-'1' (idle по
              построению, как shreg 9'h1FF txclient; параллельных загрузок idle НЕТ);
bit_cnt[3:0]  4 МЦ — 0..9 (0=idle, 1..9 — сдвиги кадра);
baud_cnt[3:0] 4 МЦ — mod-16 СВОБОДНЫМ ходом: D = bc+1, wrap натуральный —
              «счётчиковый» делитель; jam <= 1 при загрузке;
tx_run        1 МЦ — идёт передача (TXRDY = !tx_run);
adv_q         1 МЦ — регистровый хелпер тика сдвига (п.21 v8: декод не
              копируется в D-функции битов shreg);
ld_tx_q       1 МЦ — РЕГИСТРОВЫЙ строб загрузки (п.28, см. ниже).
```

**п.28 — главное отличие от hwuart v4.0.x (лекарство от стены вх.ФБ фитов
11-4/11-5):** там декод `io_wr_tx` (11 литералов) грузил shreg НАПРЯМУЮ →
16 потребителей, +42 вх.ФБ, 213/216 (99%), Placement Failed ×3. Здесь
`io_wr_tx` (12 литералов: state×3, 04h×3, IOM, !WRn, !tx_run, !ld_tx_q,
!por_run) имеет **ЕДИНСТВЕННОГО потребителя** (`ld_tx_q.D`); загрузка — на
тик позже строба (данные живы); D-функция бита shreg = 3 ПТ/~5 вх
{ld_tx_q, A[k], adv_q, shreg[k+1], shreg[k]} → все 9 бит ложатся в ОДИН ФБ
(~27 вх ≤ 36).

**Тайминг кадра (п.29):** загрузка → старт-бит '0' с этого такта; jam
`baud_cnt <= 1` → первый сдвиг (adv_q) ровно на T+16 (лаг adv_q 1 такт; jam 0
дал бы 17 — урок v8/hwuart) → старт **ровно 16 тиков**, ВСЕ переходы на сетке
16 тиков; инжекция '1' — на 9-м сдвиге стоп сам в [0]; кадр закрывается на
10-м тике ядра (TXRDY ~15-й тик стопа) — при непрерывном поллинге фактический
стоп у ПК ≥ 1 полного бита.

## Контракт (для прошивки)

1. `OUT 04h` — только при TXRDY=1 (поллинг `IN 05h` бит 1; прецедент hwuart:
   период опроса ≪ бита, потерь нет).
2. Запись при активной передаче — байт ТИХО ОТБРАСЫВАЕТСЯ (кадр не портится).
3. Окно POR: запись 04h отбрасывается (!por_run в стробе) — floated-шина
   CPU в сбросе не рождает кадр-мусор (класс v8/v3.9.3 п.18).
4. ПК-сторона: терминал/приёмник на **1 562 500 8N1** (CH340G: произвольная
   скорость, до 2 Мбит).

## Чек-лист фита (владельцу, после прогона ISE)

Опции: как у фит-3 hwuart/успешной линии — **Input Limit 16, Pterm 18,
Exhaustive OFF, DENSITY**; если ERROR 891/892 — IL 28, далее Exhaustive ON.

1. `Fitting Status: Successful`, 0 ERROR; WARNING Cpld:897 ≤ 1-2 (класс D<7>);
   **WARNING:Xst:1780 в логе синтеза БЫТЬ НЕ ДОЛЖНО** (точка приёмки
   v398_clear: в RTL нет мёртвых идентификаторов — проверено check_v1).
2. Ресурсы (прогноз п.30 шапки): МЦ **102-104**/108 (85 − 3 транзит + 20 ядро
   + 1-2 хелпера $OpTx), вх.ФБ **~190-205**/216, ПТ **~250-280**/540, рег **71**,
   ноги **72/81** (пины = базе, UCF = hdl/top_suart.ucf по LOC 1-в-1).
3. **GSR**: «Signal 'RST' mapped onto global set/reset net GSR.» + «GSR : 1»;
   ядро TXUART + FSM/шина — CLR/SET=RST; por_sh×8/por_run/делитель — вне GSR.
4. **Транзит исчез**: sod_q/tx_pass/tx_q/cpu_rst в .rpt НЕТ; `TX` = shreg[0]
   (IO-MC P39, FDCPE с PRE=RST — SET-ветка GSR, idle '1').
5. **Счётчик бода**: D-функции baud_cnt — свободный инкремент БЕЗ декода
   терминального счёта (натуральный wrap); декод ==15 живёт ТОЛЬКО в baud_tick.
6. Пины: TX P39 вых, SOD P72 вх (INP, наблюдатель), SID P73 вых, RX P38 вх;
   PGND ровно 9: {P74,P75,P76,P78,P79,P81,P95,P96,P98} (rx_int НЕТ — P75
   возвращается в PGND); clk → GCK3, RST = P1.
7. Литералы сброса в термах: RST ×1 (RESET_IN) + por_run ×2 (RESET_IN-класс,
   io_wr_tx) — `scripts/check_fit_v1.py` (после появления .rpt).

## СТАТУС 11-8веч: v2.0 НА БАЗЕ v3.9.8-clear — RTL + ВЕРИФИКАЦИЯ ГОТОВЫ, ЖДЁТ ФИТА ВЛАДЕЛЬЦА (XC95144)

Директива владельца: «Берем дизайн beta\lowsize 398_clear и переделываем txuart
на основе него». Причина (разбор фита v1.0 и вопроса «почему пропало кольцо»):
v1.0 был собран от базы v3.9.3 — до-перемычечной эпохи 25 МГц с двоичным
счётчиком mod-7 вместо кольца; на текущей плате (H1 без шунта, 50 МГц) он давал
ТРИ 2х-проблемы: бод 3,125 М (известный БЛОКЕР), CPU 7,14 МГц вместо 3,571
(X1 = 2×clk/7 — второй 2х, аудит 11-8 его пропустил), FSM/шина на clk 50
напрямую (тайминг XC95108-15 не закроет — собственное заключение v3.9.8 п.23).

**v2.0 = база v3.9.8-clear ред.2 БИТ-В-БИТ** (кольцо r0..r6 на clk 50, X1 = r0,
X2 = OR(r1..r6), clk25 = /2, por-цепь в 50-домене со стробом r0, харденинг
сброса п.20/21, FSM шины) **+ ядро TXUART v1.0, пересаженное на (clk25,
cpu_rst)**:

| Что | v1.0 (база v3.9.3) | **v2.0 (база v3.9.8-clear)** |
|---|---|---|
| Узел тактирования | счётчик mod-7 + x1_n (¬clk) | **КОЛЬЦО r0..r6** на clk 50, X1 = r0 |
| Такт ядра | clk (на плате 50 МГц → бод 2х) | **clk25** → бод = 25/16 = ровно 1 562 500 |
| CPU | 2×clk/7 → 7,14 МГц на плате (2х) | 3,571 МГц (кольцо, бит-в-бит базы) |
| FSM/шина | clk напрямую | clk25 (тайминг закрывается — доказано фитами v3.9.8) |
| GSR | сырой RST (POR-окно не покрывал) | **cpu_rst** = rst_press \| por_run (п.20: ядро чистится и в POR) |
| RESET_IN | ~(RST\|por_run) комб. | регистр **reset_q** (п.21, бит-в-бит базы) |
| Сброс кнопки | мгновенный | квалификатор ~400..440 нс (класс п.21 — приёмник кадр отбрасывает) |
| Целевое устройство | XC95108 (100/108) | **XC95144-15PQ100C** (прогноз 111–113/144) |
| io_wr_tx | 12 литералов, !por_run | + !rst_press (класс п.21e, оба источника сброса) |

Ядро (shreg/bit_cnt/baud_cnt/tx_run/adv_q/ld_tx_q, mod-16, jam, инжекция '1',
регистровый строб ld_tx_q) — **бит-в-бит v1.0**, пересажено только по такту и
сбросу. Транзит v3.7 выпилен (sod_q/tx_pass/tx_q); SOD (P72) — вход-наблюдатель
keep; SID = RX сохранён.

**Верификация:** `check_v2.py` **129/129 ПАСС** (CP1251 round-trip, двойники
синхронны, мёртвых идентификаторов в коде НЕТ — sod_q/tx_pass/tx_q + legacy
узла cnt/x1_n/…; 40+ контрольных строк базы бит-в-бит — кольцо с двойным kill,
por-цепь 50-домена, квалификатор, FSM; структура ядра на clk25/cpu_rst;
порядок объявлений). `sim_txuart_v2.py` (цикл-точная NBA-модель, ДВА домена:
