# v37G02: накопленные решения по оптимизации (проверка по .rpt/.v от 11-23)

> Проверка двух решений владельца посигнально по `retro_pcld_top.rpt`
> (фит 11-21-2026) и `top_txuart_por6_v37G01.v`. cpldfit в песочнице
> недоступен — ре-фит на машине владельца (ISE), здесь только разбор.

## Решение 1. Снять keep, где он не нужен (X2 не трогать)

**Вердикт: поддерживается.** Из 9 комбинаторных keep-МЦ (см.
`v37G01_rpt_busreg_keep_analysis.md`) снятие ранжируется так:

| Узел (МЦ) | Потребители | Снятие |
|---|---|---|
| in_wb (FB1_18) | D_OE×8 (FB1/FB3), CS_n, OE_n | **ЧИСТО** — в FB1/FB3 биты состояния ФСМ уже в матрице |
| fsm_rddone (FB1_7) | FB4 | **ЧИСТО** — в FB4 rd_seen.LFBK + RDn уже есть |
| fsm_wrdone (FB2_6) | FB4, FB5 | **ЧИСТО** для FB4; FB5 +2 вх (запас 32/4 есть) |
| kbcol_wr06 (FB2_2) | CE kbcol_q в FB3 | **ЧИСТО** — в FB3 io_wr + addr_latch<0..2> уже есть |
| bus_ld_t1 (FB1_13) | D-мультиплексоры FB1+FB3 | **СВОП 1:1** — в FB3 (36/0) RDn взамен bus_ld_t1 |
| bus_ld_t2 (FB4_4) | D-мультиплексоры FB1+FB3 | **СВОП 1:1** — WRn взамен bus_ld_t2 |
| rd_drive (FB4_2) | A<0..7> в FB1+FB2 | **НЕСУЩИЙ** — FB2 нужны rd_seen/RDn/ALE (+3 вх) при 36/36 |
| io_wr (FB2_5) | FB2/FB3/FB5/FB6 | **НЕСУЩИЙ** — FB6 (32/4) нужны 3 бита состояния+WRn+IOM (+5 вх) |
| io_wr_tx (FB2_4) | CE shreg в FB6 и др. | **НЕСУЩИЙ** — FB6 не хватает tx_idle (4 бита bit_cnt) |

Итог: **4 МЦ чисто + до 2 свопами = до 6 МЦ**; три несущих keep
(rd_drive, io_wr, io_wr_tx) остаются. Запас входов: FB1/FB2/FB3 = 36/0,
FB4 = 31/5, FB5/FB6 = 32/4. X2 — согласовано, keep не трогать (keep на
выходе только фиксирует пин, МЦ не расходует).

Замечания:
- ФСМ скомпакчен фиттером (`fsm_encoding = "compact"`): коды состояний
  после ре-фита не обязаны совпадать с localparam, поэтому подстановки
  «сырых входов вместо keep-узлов» гарантируются только ре-фитом.
- Ре-фит меняет раскладку глобально → v37G02 = новая пара jed+hex,
  аппаратная проверка обязательна; `retro_pcld_top.jed` (v37G01)
  остаётся fallback-парой.

## Решение 2. RESET_CPU: уйти от клока CLKOUT на ce_3125 (домен clk)

**Вердикт: поддерживается, с тремя поправками фактов.**

Подтверждено по .rpt (стр. 741): `FTCPE_RESET_IN: FTCPE port map
(RESET_IN, RESET_IN_T, CLKOUT, RST, '0')` — три триггера tt<0> (FB4_7),
tt<1> (FB4_6), RESET_IN (FB4_3) тактируются CLKOUT через Product-Term
Clock; CLR=RST (GSR) у всех трёх. CLKOUT в .v используется только
модулем RESET_CPU.

Поправки:
1. **Второй домен — это FB4, не FB5.** CLKOUT — элемент 4 в списке
   сигналов FB4; вход-пин CLKOUT (83) сидит на IOB FB4_2. В FB5 — ноль
   упоминаний CLKOUT.
2. **t0_q/x1_q в матрице FB4 отсутствуют** — аргумент «они уже
   присутствуют» не работает. Экономия входа всё равно достигается:
   baud_cnt<0>,<1>,<2> уже в матрице FB4 (T-термы двоичного счётчика),
   поэтому строб декодируется внутри FB4 без новых входов:
   −CLKOUT + 0 = **NET −1 вход FB4** (31/5 → 30/6).
3. Триггеров три, но это не «tt[2:0]+что-то»: tt<0>, tt<1> и
   **RESET_IN = tt[2]** — сам выходной регистр (3xFTCPE, как в README).

Ресурсы: МЦ не меняются (3 регистра остаются в FB4_3/6/7); ПТ: −1
(клочный терм PTC) + 3 (ce-литерал в T-термах); входы FB4: −1. Все
триггеры кристалла — единый домен GCK3 (X1/X2/t0_q уже на clk и вне GSR
по замыслу — FTCPE_X1/X2, стр. 767/769 rpt).

Семантика RESET_CPU сохраняется (проверено против модуля):
- GSR: tt=000 при кнопке, RESET_IN=0 — CLR=RST остаётся;
- POR: tt=000 → счёт → стартовый импульс ~1,3 мкс (baud_cnt тоже на
  GSR — стартуют синхронно из 0);
- ширина ≥3 полных такта CLKOUT: конверт отпускания **3,25..4,125
  периода** (сейчас 3,03..4,00) — во время окна сброса io_wr_tx=0
  (затворт RESET_IN в его определении), счётчик не возмущается,
  спейсинг строба ровно 8/8/9 клк (mod-25: срабатывания на 7/15/23);
- безглитчевость: RESET_IN = tt[2], регистровый выход.

Эскиз:

```verilog
// ce_3125: 1 клк из 8 (3,125 МГц). В окне сброса io_wr_tx = 0,
// поэтому baud_cnt невозмущён: срабатывания 7/15/23, спейсинг 8/8/9 клк.
// ВНИМАНИЕ: BAUD_DIV менять только вместе с этим блоком (ширина сброса).
wire ce_3125 = (baud_cnt[2:0] == 3'b111);

always @(posedge clk or posedge RST) begin
  if (RST) begin
    tt <= 3'b000;
  end else if (ce_3125 && !tt[2]) begin
    tt[0] <= !tt[0];
    if (tt[0]) tt[1] <= !tt[1];
    if (tt[0] && tt[1]) tt[2] <= !tt[2];
  end
end
assign RESET_IN = tt[2];
```

Альтернатива (отдельный toggle-FF clk/8) даёт точные 4 периода, но
+1 МЦ и 2 свопа входов в FB3 (t0_q/x1_q туда не заведены) — дороже,
признана излишней.

Риски/проверки:
1. Фаза отпускания RESET_IN: было «ровно на фронте CLKOUT», станет
   «фаза X1/clk» — детерминированный сдвиг на задержку CLKOUT
   процессора (t_CLCO ИМ1821ВМ85А). Один раз посмотреть осциллографом
   RESET_IN vs CLKOUT (оформить п. debug-report).
2. CLKOUT остаётся пином-наблюдателем (keep уже стоит, стр. 76 .v,
   пин 83 сохраняется).
3. UCF-комментарий «CLKOUT тактирует RESET_CPU» обновить.

Бонус надёжности: RESET_IN перестаёт зависеть от исправности
процессора/цепи CLKOUT (сейчас — курица-яйцо: нет CLKOUT → счёт стоит →
RESET_IN не отпускается, мёртвую плату не отличить от мёртвого CPLD).
После перевода RESET_IN формируется всегда — плата диагностируется без
рабочего CPU.

## Порядок внедрения

Две отдельные сборки, не валить в одну: (а) снятие чистых keep (4 МЦ),
(б) ce_3125. Каждая — своя пара jed+hex и аппаратный тест; при
недоступности cpldfit — ре-фит у владельца. После обеих: резерв
~10 МЦ (6 в FB3 + до 6 освобождённых) при одном клок-домене.
