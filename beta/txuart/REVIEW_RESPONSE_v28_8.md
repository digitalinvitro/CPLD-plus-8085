# Ответ на ревью `REVIEW_top_txuart_v28_8.md` — вердикты по каждому пункту

Дата: 2026-11-16. Метод: каждое проверяемое утверждение сверено с кодом
(`top_txuart_por6_v28_8_utf8.v`, `top_txuart_v28_8.ucf`, fw, history) и/или
перепроверено независимой цикловой моделью (`scripts/check_o3_underflow.py`).
Вердикты: **ПРИНЯТЬ** / **ПРИНЯТЬ К ПРОВЕРКЕ** (нужно железо/схема/даташит) /
**ПРИНЯТЬ С ПРАВКОЙ** (суть верна, числа или предпосылки скорректированы) /
**ОТКЛОНИТЬ**.

Общая оценка ревью: **высокое качество**. Найдены два реальных исходных бага
(О-1, О-2), один латентный (О-3 — подтверждён моделью), вскрыт процесс-дефект
(комментарии-контракты UCF/RTL отстали от RTL на 2-3 версии — Н-6/7/8/9,
Д-12) и предложена правильная валюта оптимизаций (входы ФБ, а не МЦ).
Спорные места: числа Н-3 и Р-2 посчитаны на идеализированной модели ISR,
заявление о подавлении помех в Р-1 внутренне противоречиво — детали ниже.

## 1. Ошибки

| № | Вердикт | Резюме |
|---|---------|--------|
| О-1 | **ПРИНЯТЬ** | Подтверждено: `assign seg = {1'b0, ~seg_q}` (стр. 1514) при активном-0 выходе ⇒ dp-пин (P60) постоянно низкий ⇒ dp горит на всех разрядах, программно не гасится (порт 00h пишет только A[6:0]). Фикс `seg[7]=1'b1`: 0 МЦ, 0 ПТ. Железная проверка — «8888 без точек» до первой записи в 00h |
| О-2 | **ПРИНЯТЬ** (с оговоркой) | Подтверждено: `dig_q` INIT=4'hF и ветка сброса `dig_q <= 4'hF` (стр. 1151/1306) + `dig = ~dig_q` ⇒ все 4 PNP-базы прижаты к 0 на весь POR/инициализацию, ≈68 мА по базам. Фикс INIT/сброс = 4'h0: 0 МЦ. Оговорки: (а) исчезает самотест «8888» при включении — если нужен, его зажигает fw; (б) 240 Ω в базе PNP — вопрос к схеме (см. Д-3), не к этому фиксу |
| О-3 | **ПРИНЯТЬ** (подтверждено моделью) | Воспроизведено независимо: при OUT 06h,0 на первом клке после снятия `tmr_wr06` гейт `tick_step && !RST75_r` видит старый RST75_r=0 → `0−1=F`. | О-4 | **ПРИНЯТЬ К ПРОВЕРКЕ** | Структура подтверждена (`S_WB4: state <= S_IDLE`, стр. 1367; правило п.6 «из WB в T1H только через IDLE»). S_T1H : S_IDLE` — 0 МЦ и снимает лишний такт, НО: (а) перед применением — осциллограф WRn↑→ALE↑ (п. Б-4) и tb-прогон; (б) инвариант п.6 в шапке должен быть переописан (у него была причина: удержание addr_latch на время writeback) |
| О-5 | **ПРИНЯТЬ КАК РИСК, К ПРОВЕРКЕ** | Логика подтверждается: AH8..AH14 — входы-наблюдатели без регистра/драйвера, защита п.4 покрывает только A0..A7. Вариант 1 (сверка WRn↑→смена A8..A14 с окном /WE 40…200 нс) — обязательный пункт Б-4. Вариант 2 (WB3) — только с проверкой t_AH памяти. Вариант 3 (wait-state через READY) — это Р-10/v3, READY сейчас прибит к '1'. До измерений шину не трогать |
| О-6 | **ПРИНЯТЬ НАПРАВЛЕНИЕ, ОТДЕЛЬНЫМ ПРОГОНОМ** | Констатация верна: даташит требует «X2 left open», а v2.4-2.8.7 работают активным драйвом «вопреки» (и T1-убийство генератора это подтверждает: X2 — выход внутреннего инвертора). НО: X2 — самый железочувствительный узел (урок T1), open никогда не пробовался; включать только отдельным прогоном с осциллографом на CLKOUT до/после (Б-3), не в общий пакет. Оговорка ревью про bus-hold корректна |
| О-7 | **ПРИНЯТЬ** | Подтверждено: атрибут закомментирован (стр. 1140). One-hot дал бы +4 МЦ = 109/108 — не влезает; оставлять это на усмотрение эвристики XST нельзя. Фикс `(* fsm_encoding = "compact" *)` — 0 МЦ, чистая страховка |

Сейчас спасает только дисциплина fw (глушилка вектора + TMOFF/TMON с SIM 78h). Действия: (1) **обязательно** — записать в контракт шапки/README «первый OUT 06h обязан быть раньше первого EI»; (2) INIT RST75_r=1 — опционально, только с железной проверкой (статический высокий уровень фронта не создаёт, но клоны CA80C85B проверить); с ним обновить tb-контракт «RESET → RST75=0» и историю |

## 3. Двусмысленности

## 4. Избыточность и предложения

| № | Вердикт | Резюме |
|---|---------|--------|
| Р-1 | **ПРИНЯТЬ С ПРАВКОЙ** (пакет v2.9) | Идея верна: POR и квалификатор — одна абстракция «сброс, пока вход не устойчив N сэмплов», 16 МЦ → 13, −3 МЦ, снятие квалифицировано 1,28 мкс (×4 к сейчас), debounce-свойство реальное. НО заявление «помеха 40/80/160 нс подавлена» внутренне противоречиво: при `por_run = \|por_sh` любая помеха ≥1 строба por_ce засчитывается и даёт **валидный** сброс 1,28 мкс > 960 нс нормы — то есть порог подавления фактически исчезает (сейчас: <320 нс не сбрасывает вообще). До реализации: переопределить семантику помех явно (принимаем ли короткий паразитный сброс?), и закрыть Д-1 (полярность/подтяжка) — иначе сливать нечего |
| Р-2 | **ПРИНЯТЬ С ПРАВКОЙ** (пакет v2.9) | Направление верное: 4-битный таймер — худший обмен дизайна (2 МЦ за 6-кратный рост числа ISR). Но «налог 19,4 % → 3,2 %» посчитан на идеализированной модели (34T/ISR); реальный налог ≈45-50 % ЦП (67T tiny / 543T slot, fw-шапка честно говорит «~50 %»), при N=84 (слот = 1 фронт) налог ≈ 174/510 ≈ **34 %** — выигрыш ~12-15 п.п., не −16. Требует fw-изменений (TMN=84, слот = каждый фронт, E-счётчик долой) — т.е. это уже v2.9, не патч v28.8. Относительный джиттер ×7 лучше — верно |
| Р-3 | **ПРИНЯТЬ КАК АЛЬТЕРНАТИВУ ДЛЯ v2.9** | Элегантно: защёлка периода после П-5 стоит 4 МЦ (не 8), период ровно 56,00 мкс, фронт-уровень 4 мкс ≫ 320 нс такта CPU — ловится гарантированно без hold-терма, из ISR уходит ре-арм, каденция перестаёт зависеть от ISR (закрывает Н-3). Пробелы: СТОП при N=0 не описан (нужен явный признак останова — иначе перезагрузка 0−1=F); это второй взаимоисключающий дизайн уровня после v28.8 — выбрать одно. Лучший финал: Р-3 + 7-битный latch (после Р-1) — точный период, 1 ISR/слот, налог ~34 % |
| Р-4 | **ПРИНЯТЬ** (предпосылка скорректирована) | Асинхронная форма `posedge clk or posedge cpu_rst` есть только в 2 блоках из 9 (ядро TXUART, стр. 1259, и главная логика, стр. 1298) — «весь остальной дизайн» — преувеличение, НО суть верна: таймер платит литералом cpu_rst в D-путях 5 бит + входом ФБ. Перевод в общую форму: −5 ПТ, −1 вход ФБ, 0 МЦ, узел попадает под чек-лист п.f. INIT tmr_cnt=F через PRE — легально |
| Р-5 | **ПРИНЯТЬ** | Узел `io_wr` — правильная валюта: −4 сети в 3-4 ФБ = −12…16 входов ФБ при дефиците именно UIM; фиттер уже держит такой узел ($OpTx$FX_DC$91) ⇒ вероятно 0 МЦ. Симметричный вывод по чтению (резерва нет) — проверить по .rpt |
| Р-6 | **ПРИНЯТЬ** | POR_W не используется и врёт вместе с именем файла; generate без else = тихая сборка «не того исходника» без warning. Убрать параметры/генерейт (или else $error) — 0 МЦ, минус класс ошибок |
| Р-7 | **ПРИНЯТЬ** = О-6 | −1 МЦ, −1 вход ФБ, −1 ПТ, минус класс X2-аудитов; только отдельным железным прогоном с осциллографом |
| Р-8 | **ПРИНЯТЬ КАК ЕСТЬ** | «Что не трогать» — анализ корректен: sentinel/idle-варианты shreg ломаются на 0x00/0xFF (проверено ревью), делитель и 3-битный state — минимум, addr_latch+bus_reg несливаемы. Зафиксировать в шапке как границы оптимизации |
| Р-9 | **ОТКЛОНИТЬ** (согласен с ревью) | Слияние seen-триггеров ослабляет защиту записи от глюка RDn — 1 МЦ того не стоит. Помечено «последняя очередь» — и той нет |
