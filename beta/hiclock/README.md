## v3.8 (clk10-52, 2026-10-29) — делитель = one-hot кольцо вместо двоичного mod-5

Идея владельца и коллеги: «использовать как основу кольцевой счётчик на
сдвиговом регистре; +2 триггера против текущего — высвободит нужные
ресурсы по FB». Вердикт: **идея верная, и она оказалась даже дешевле,
чем думали авторы** — вместо +2 триггеров узел стал на 1 триггер
КОРОЧЕ. Ресурсная стена по фиту v3.6 (10-29): МЦ 102/108, входы ФБ
197/216 — жмут именно ВХОДЫ ФБ (4 ФБ на 35-36/36, FB6 Exhausted),
птермов свободно 50%. Узел платил входную ренту сразу в два ФБ:
FB6 (пины X1/X2) ел cnt<0..3> + x1_p/x2_p/x1_n = 7 входов, FB4 —
cnt<0..3> + x1_n = 5 (+копия декода por_ce $OpTx$FX_DC$163 на 4
литерала cnt).

Что сделано (п.14 шапки v3.8):

| Элемент | v3.6 (mod-5) | v3.8 (кольцо) |
|---|---|---|
| Регистры узла | cnt<0..3> (4! cnt<3> — балласт 4-го бита) + x1_p + x1_n + x2_p = 7 FF | r0..r4 + x1_n = 6 FF (**−1 МЦ**) |
| Декоды равенства | 4 шт (==4 wrap ×2, ==1, ==2, ==3) — класс п.9, аудит «обе полярности!» на каждом фите | **0** (состояние = выход триггера; терять полярность нечему) |
| x1_p/x2_p | отдельные триггеры-двойники | **сокращены**: x1_p ≡ ~r0, x2_p ≡ r0 (один posedge) |
| X1/X2 | x1_p^x1_n / x2_p^x1_n | (~r0)^x1_n / r0^x1_n — SOP по 2 птерма, функции различны (same-D слияние невозможно, п.10) |
| por_ce | (cnt==4)\|(cnt==1), 2 птерма × 3-4 литерала | r1\|r4 — 2 птерма × 1 литерал |
| Птермы узла (с копией декода) | 11 | 8; макс. ширина литерала 4 → 2 |
| Входы ФБ от узла | FB6: 7, FB4: 5 | FB6: 6, FB4: 0..2 |
| Нелегальные состояния | выплывает до 12 тактов | **≤2 фронта** (самоочистка «убей преемника» + рестарт из 00; наивное кольцо НЕ годилось: пара '1' ходит вечно, 00000 = мёртвый клок) |

Ключевые эквивалентности (доказаны трассировкой фронтов, закреплены
симуляцией): x1_p(t) ≡ ~r0(t) и x2_p(t) ≡ r0(t) после любого posedge;
x1_n — без изменений (set r2 / clear r3 = те же фронт-пары, что
cnt==2/3). Единственное отличие от v3.6 — до ПЕРВОГО posedge X1='0'/
X2='1' (v3.6: 1/0): CPU всё это время в POR, схемно незначимо; с
первого фронта X1/X2/por_ce/por_run совпадают с v3.6 пофронтово.

## v3.7 (clk10-51, 2026-10-29) — TX-маска удалена: захват по первому SOD='1'

Директива владельца: «почему мы вообще должны обращать на TX особое
внимание, если он полностью определяется софтом? Артефакт можно вырезать
полностью: один триггер, в сбросе CPLD — '1', INIT='1', задержка
стробирования на 25 МГц — ничто». Вердикт: ПРА на ~90% — механизм
(регистр, INIT=1, async set, 25 МГц) принят дословно; НО голый транзит
возвращал бы баг v2-эпохи: сброс CPU очищает SOD в '0' (датасшит
IM1821ВМ85А, вывод SR: «...триггеров входа INR4 и ВЫХОДА TFD...»), и до
первого SIM прошивки (~4-20 мкс, TXIDLE fw_mon v5) линия '0' = «фиктивный
start-bit» → пустой фрейм в терминале — ровно то, против чего маска
заводилась. Окно закрыто СХЕМНО, без счётчика:

| Триггер | Роль | Сброс/INIT |
|---|---|---|
| `sod_q` | синхронизация входа SOD по clk 25 МГц (метастабильность гасится до использования; статический путь пин→пин разорван) | без сброса, INIT=0; должен лечь в IO-MC входа SOD P72 |
| `tx_pass` | «линия захвачена прошивкой»: взводится первым сэмплом SOD='1' после сброса | async clear по cpu_rst, INIT=0; 1 лог. MC |
| `tx_q` | выходной регистр TX: до захвата — '1' (чистый idle), после — транзит sod_q | async set по cpu_rst, INIT=1; должен лечь в IO-MC пина TX P39 |

Что это даёт против v3.6: txm_cnt<7:0> (8 FF, ~9 МЦ, почти весь FB4) и
параметр TXM_W удалены → прогноз ~102 → **~94/108 МЦ**; окно SOD=0 покрыто
ПО СТРОЕНИЮ (TXM_W, запас 1,28x и привязка к частоте X1/CPU упразднены —
работает на 3,125/5/6,25 МГц и с любой длиной init); сброс/кнопка уводят
TX='1' мгновенно (async set, без клока); латентность транзита 40-60 нс
(0,2-0,3 такта CLK 200 нс; 0,05% бита 9600). Требование к прошивке одно:
первое касание SOD после сброса = SOD:=1 (fw_mon v5 делает это в TXIDLE;
любой soft-UART начинает кадр с idle '1'). Теоретическая уязвимость
(документирована в п.13 шапки): импульс SOD='1' длительностью ≥1 такта
25 МГц в окне ложно открыл бы захват — физически невероятен (вход CPU в
сбросе статичен, звон шины мВ-уровня до VIH не достаёт); лечение, если
когда-нибудь проявится: захват по 2 сэмплам подряд (+1 FF).

Решение владельца: внешний каскад НЕ трогаем (U7 → шунт H1 1-2, DIV=GND, /4 →
GCK3 = 25,00 МГц), делитель перестраивается ВНУТРИ дизайна. Вариант «/2»
(12,5 МГц → CPU 6,25 — ВНЕ ТУ) отклонён владельцем как разгон. Цель:
X1/X2 = 10 МГц → внутренний /2 ВМ85А → **CLK = 5,000 МГц — ровно паспортный
максимум**.

25/10 = 2,5 — деление полуцелое, toggle-каскадом недостижимо. Новая ветка
`g_div2p5` (выбор: CLK_DIV=2 + НОВЫЙ параметр CLK_HALF=1): mod-5 счётчик
(cnt, posedge) + пара x1_p (posedge) / x1_n (negedge), X1 = x1_p ^ x1_n:

| Сигнал | Тактирование | D / условие | INIT | Интервалы '1' |
|---|---|---|---|---|
| cnt (mod-5) | posedge | (cnt==4) ? 0 : cnt+1 | 0 | — |
| x1_p | posedge | (cnt != 4) | 1 | [0,160)+[200,360)… нс (по 160) |
| x1_n | **negedge** | set cnt==2 / clear cnt==3 | 0 | [60,100)+200k (по 40 нс) |
| x2_p | posedge | (cnt == 4) = НЕ D(x1_p) | 0 | = ~x1_p |
| X1 | — | x1_p ^ x1_n (комб.) | — | узор «11100» по полутактам |
| X2 | — | x2_p ^ x1_n (комб.) | — | = ~X1 ТОЧНО |

Ключ: у «наивного» posedge-деления /2,5 фронты 80/120 нс (период плавает);
negedge-сдвиг x1_n выравнивает ПЕРИОД — фронты X1 через РОВНО 100 нс
(10,000 МГц, high 60 / low 40). Duty X1 процессору безразличен: внутренний /2
тактируется ФРОНТАМИ → CLK = 5,000 МГц, период РОВНО 200 нс, duty РОВНО 50/50
(лучше, чем 40/60 у наивного варианта).

Гарантия противофазы v3.5 сохранена ПО ПОСТРОЕНИЮ: D(x2_p) = (cnt==4) ≠
D(x1_p) = (cnt≠4), INIT инверсный → same-D слияние невозможно; X2 = x2_p ^
x1_n = ~x1_p ^ x1_n = ~X1 ТОЧНО. Регистры ТОЛЬКО существующие
(cnt/x1_p/x1_n/x2_p) → прогноз ~98/108 MC (−t0_q/−x1_q/−x2_q ветки div4,
+cnt 3 +x1_p +x1_n +x2_p).

Верификация (`scripts/sim_v36_div2p5.py`, точная семантика RTL, 200 мкс):
**ПАСС** — инвариант X2==~X1 (10000/10000 полутактов), узор X1 «11100»,
период РОВНО 100 нс, CLK процессора РОВНО 200 нс / 50/50, por_ce 120/80 нс
(среднее ровно 100), POR 820 нс ≥ нормы 600 нс, TX-маска 25,5 мкс. Регрессия
v3.5-веток (2/4/5/6/8/10) — ПАСС (`scripts/sim_v35_x2phase.py`).

Последствия (пересчёт от v3.4, всё в ТУ): CLKOUT = 5,000 МГц duty 50%; POR
800 нс (запас 1,33x — тот же); окно TX-маски 25,6 мкс против окна SOD=0
~4-20 мкс (запас 1,28x — тот же, TXM_W=8 не тронут); терминал 6000 → **РОВНО
9600 8N1** (ПЗУ fw_mon v5 не перешивается: 4800 @ 2,5 → 6000 @ 3,125 → 9600
@ 5 МГц).

ВНИМАНИЕ (п.9 шапки v3.6): в ветке 4 ДЕКОДА (==4/==1/==2/==3) — mod-5 иначе
недостижим; аудит .rpt по чек-листу g)-h) ОБЯЗАТЕЛЕН (полярности декодов,

## История v3.5: почему вердикт clk10-46/47 снят (доказательство clk10-48)

База: стабильный релиз **v3.4** (`hdl/top_suart.v`, коммит `670c4da`, фит
2026-10-27 10:06PM: 95/108 MC, 243/540 PT, 213/216 FB-входов, 59/108 FF,
72/72 ноги по UCF, GCK3-only, GSR не используется — железо ПАСС clk10-38).
`hdl/` не тронут (правило №1 beta/): v3.5 живёт ТОЛЬКО здесь, в `hdl/`
переедет отдельным релизом по команде владельца.

## Почему вердикт clk10-46/47 снят (доказательство clk10-48)

1. cpldfit — технологический фиттер: он НЕ ИМЕЕТ ПРАВА менять функцию
   пришедшего нетлиста.
2. Фит v3.4 (hdl/retro_pcld_top.rpt, 10-27 10:06PM) собран из комбинационного
   `assign X2 = ~X1` — его функция ОБЯЗАНА быть «X2 = ¬X1» при всех t. Фиттер
   реализовал её законной репликацией регистра: `FDCPE(X2, X2_D, clk)`,
   Init X2=RESET (комплементарен X1=SET). Такая репликация корректна ТОЛЬКО при
   `X2_D = ¬(X1 XOR t0_q)` — т.е. инверсия свёрнута ВНУТРЬ пятого (XOR-B)
   продукта макроячейки XC9500 (PT5 = {¬t0_q}); выходной pin = Q, Init=RESET —
   всё сходится. (Аргумент clk10-47 «свёртка исключена, init был бы SET»
   разбирал свёртку на ВЫХОДЕ (pin=~Q); свёртка на ВХОДЕ XOR init не меняет.)
3. Этот v3.4-фит рендерится в отчёте БАЙТ-В-БАЙТ той же строкой
   `X2_D <= X1` / `XOR` / `X2_D <= t0_q` — следовательно, такая строка НЕ
   РАЗЛИЧИЕТ XOR и XNOR: рендерер pseudo-VHDL слеп к полярности XOR-B входа
   (при этом NOT внутри AND-термов он печатает исправно — вся таблица
   txm_cnt/A_I это показывает). В целом .rpt cpldfit для XC9500 других XOR
   не содержит — калибровочного примера нет, и.literal «same-D» читать нельзя.
4. Следствие: **по .rpt фиты v3.4 и v3.5 неразличимы в принципе** — явный
   регистр v3.5 `x2_q <= ~(x1_q ^ t0_q)` оптимизируется в ТО ЖЕ 2-PT
   XOR-ядро (FB6: X2 = 2 PT / 2 вх {X1, t0_q}). Дифф hdl(10-27) vs 6:20PM —
   506 строк: дата, переименования $OpTx$, перестановка слагаемых — это
   ожидаемая картина ОДИНАКОВОГО нетлиста, а не улика «старого исходника».
   «Сети x2_q нет» — тоже не улика: регистр, управляющий портом, фиттер всегда
   переименовывает в имя порта (X2).
5. Железный аргумент: при same-D X2(n+1) = X1(n+1) — противофаза
   схлопывается за 1 такт после POR. Устойчивая противофаза на осциллограмме
   = исполняется X2 = ¬X1. Осциллограф и .rpt теперь говорят одно и то же.

## Суть v3.5 (зачем; остаётся в силе)

Фит v3.4 поднял комбинационный `assign X2 = ~X1` в регистр (репликация).
Функция получилась верной, но ПО СЛУЧАЙНОСТИ фиты: полярность была свёрнута
фиттером внутрь XOR-B PT, что в отчёте неотличимо от реального same-D слияния.
v3.5 делает противофазу СВОЙСТВОМ RTL — регистр `x2_q` с D, отличным от D(x1),
same-D слияние невозможно по построению:

| Ветка CLK_DIV | X1 | X2 (v3.5) | Гарантия |
|---|---|---|---|
| 2 | `x1_q <= ~x1_q` | `x2_q <= x1_q` | D = `x1_q` != `~x1_q`; init (1,0) |
| **4 (цель)** | `x1_q <= x1_q ^ t0_q` | `x2_q <= ~(x1_q ^ t0_q)` | D = XNOR != XOR; противофаза с 0-го такта (x1: 1,1,0,0…; x2: 0,0,1,1…) |
| чётные N>=6 | toggle при `cnt==MEV` | toggle при `cnt==MEV` | синхронная toggle-пара, init (1,0) |
| нечётные (не исп.) | `X1 = x1_p ^ x1_n` | `X2 = x2_p ^ x1_n` | `x2_p` — двойник `x1_p` с инверсным INIT |

Инициализация: `x1_q = 1`, `x2_q = 0` (POR); keep на порте X2 сохранён.

## Остаточный контроль (1 минута, формальность)

Запуск осциллографа по ФРОНТУ X2 (CH2, инверсия ВЫКЛ): синус X1 должен ПАДАТЬ
через точку запуска = противофаза. Если РАСТЁТ — проверить инверсию канала;
при подтверждённой фазе «в фазе» — гигиена ISE (в Sources один top-файл
v3.5, Cleanup, Re-Run All). NB: даже нетлист div4 у v3.4 и v3.5 идентичен
(доказано диффом) — на функцию железа выбор исходника не влияет; различие —
структурная гарантия different-D в RTL v3.5.
