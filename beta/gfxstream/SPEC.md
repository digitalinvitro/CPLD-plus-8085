# beta/gfxstream — GFXSTREAM v1: графический поток по UART 1М (спецификация)

> Решение владельца 11-10-4 (выборы после анализа полосы): **рендер — GUI-окно
> WinForms из PowerShell; формат — 1bpp ч/б; геометрия — 160×100; поток —
> TYPE-таблица (расширяемая); цель — 25 FPS; шаг 0 — прошить p04 (TX_BOTH=0)
> и проверить 97,7% линии.**

## 1. Полоса канала (доказано TXSTRESS v1.1 + разбор исходника)

| Режим | Темп | % линии 100 000 Б/с |
|---|---|---|
| Стационарный цикл (прошит, 60 с) | 69 770 Б/с | 69,8% |
| FLOOD TX_BOTH=1 (прошит) | 74 405 Б/с = 42T | 74,4% |
| **FLOOD TX_BOTH=0 (`txstress_v11_p04.hex`, собран, не прошивался)** | **97 656 Б/с = 32T** | **97,7%** |
| Физический потолок (кадр 31,25T) | 100 000 Б/с | 100% |

Потолок софта = 32T, ниже нельзя:
- цикл 8085 `MOV A,C(4)+OUT 04h(10)+INR C(4)+DCR B(4)+JNZ(10)` — убирать
  нечего (OUT и JNZ несжимаемы);
- запись в занятый TX ядро **отбрасывает** (RTL hwuart v401 «отброс при
  busy»; железное доказательство — SPRINT 31T: принята ровно половина,
  U=8192 из 16384, 52/52 цикла);
- опрос TXRDY (`IN 05h`, бит 1) стоит ≥24T/Б — дороже слепых 32T;
- зазор 32T−31,25T = 240 нс/Б — **константа** (оба клока от одного 25 МГц);
- остаток 2,3% — только CPLD FIFO/пейсинг, не влезает в XC95108 (фит 103/108);
- бод >1М бессмысленен: лимит — CPU, его темп от бода не зависит.

## 2. Бюджет кадра при 25 FPS (период 40 мс)

| Темп | Байт/кадр | Посылка TYPE 01 (2 006 Б) | Запас CPU |
|---|---|---|---|
| 74,4К (42T, fallback) | 2 976 | 27,0 мс | 13,0 мс |
| **97,7К (32T, p04)** | **3 906** | **20,5 мс** | **19,5 мс (~61К T-сост.)** |

## 3. Кадр на проводе

```
Кадр = A5 5A [TYPE] [N_LO] [N_HI] [SEQ] [payload]
```
- Магия `A5 5A` — точка ресинка (по прецеденту лендмарков TXSTRESS);
- `TYPE` — тип кадра; `N` — длина payload (LO/HI); `SEQ` — счётчик кадров
  mod 256 (контроль пропусков, отброс просроченных);
- заголовок 6 Б ≈ 0,15–0,3% кадра.

**TYPE 01 — полный 1bpp 160×100** (payload 2 000 Б): 100 строк × 20 Б,
строки сверху вниз, бит MSB = левый пиксель, 1 = светлая точка.

**TYPE 02 — дельта строк**: маска изменённых строк 13 Б (ceil(100/8), бит i
= строка i изменена) + для каждой `[номер 1 Б][20 Б]`. Выгоден при <95
изменённых строк.

**TYPE 03 — RLE**: пары `[счёт 1..255][байт]` до конца payload — для полей,
заливок, осциллографа.

**TYPE 04 — текст 80×25 CP866** (2 000 Б) — рендер моноширинным шрифтом.

## 4. Пейсинг и ОЗУ

- 25 FPS: старт кадра по таймеру платы каждые 40 мс, квитанций нет (у UART
  нет backpressure); ПК по SEQ отбрасывает просроченные, FPS-метр в рендере.
- Двойной буфер: FB_A + FB_B = 2×2 000 = 4 000 Б из 32 768 (12%); рисование
  в теневой буфер, отправка из другого, swap по SEQ.
- Отправка — тот же доказанный 32T-цикл; поток из ОЗУ: `MOV A,M(7)+OUT(10)+
  INX H(6)+DCR B(4)+JNZ(10) = 37T` → развёртка ×2 + набивка NOP-ами до 32T
  (выше 31,25T уходить нельзя — перебор = отбросы).

## 5. Ожидания контрольного прогона p04 (шаг 0)

Прошить `rom/txstress/txstress_v11_p04.hex`, прогон `.\uart_speed.ps1 -Port COM13`:
- FLOOD **97 656 Б/с (97,7%)**, цикл **~845 мс / 76 711 Б (~91%)**, ~70 циклов
  за 60 с; SPRINT U=8 192 (фаза ~110 мс, приём 74 405 Б/с), BURST U=2 816
  (~42 мс, 67 368 Б/с);
- паттерн +1 ЦЕЛ, B=7/7, токены +7/цикл, ЧУЖИХ 0 — критерии те же;
- блок ОЖИДАНИЙ утилиты печатает старые цифры 42T (74 405) — это НЕ ошибка:
  v1.3 заморожена с ожиданиями TX_BOTH=1, вердикт считается по паттерну/
  лендмаркам/U и для p04 действителен.
