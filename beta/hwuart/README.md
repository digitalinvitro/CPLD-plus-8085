# beta/hwuart — аппаратный UART-трансивер на базе lowsize v3.9.3

**Директива владельца (11-3):** «Отставим пока эту затею [txclient], попробуем на варианте 3.9.3 lowsize сделать полноценный UART трансивер, пусть полудуплексный, применяя в том числе и мои наработки по размещению UART в малых CPLD. Заведи каталог beta\hwuart и размести дизайн там.»

**База:** `beta/lowsize/top_suart_por6_v393.v` (v3.9.3, фит 11-2 9:54PM **прошит и работает**:
85/108 МЦ, 195/540 ПТ, 171/216 вх. ФБ, 54 триггера, 72/81 ноги, сброс → GSR).
**Правило линии:** база бит-в-бит, UART ложится ТОЛЬКО на свободный ресурс + ресурс выпиленных
soft-UART-транзитов. Дисплей/клавиатура/FSM/шина/writeback/POR — не тронуты.

## Спека (выбор владельца, 11-3)

| Параметр | Значение | Основание |
|---|---|---|
| Скорость | **1 923 077,8 бод 8N1** (25 МГц / 13) | как txclient; ровно 13 тиков/бит; CH340G проверен |
| Доступ CPU | **IO-порты**: `OUT 04h` = TX, `IN 04h` = RX-байт, `IN 05h` = статус | декод по `addr_latch[2:0]` (уже в матрице); 04h-07h — резерв от удалённого UART (Task 69) |
| Прерывание | **RXRDY → RST 7.5 (P75)**, уровень = `rx_full` | прецедент 01_timer: P75→RST 7.5 проверена железом (UART-тест v4) |
| Транзиты v3.9.3 | **TX-транзит выпилен** (sod_q/tx_pass/tx_q, −3 МЦ); **SID = RX сохранён** (наблюдатель входа, 0 доп. МЦ: IO-MC и так был; старый софт-UART-ввод RIM и diag6 продолжают работать) | решение владельца «выпилить оба»: TX-транзит заменён аппаратурой, SID-пин обязан чем-то держаться — транзит дешевле и полезнее константы |
| Кадр | 8N1, RX терпит длинный стоп | стандарт терминалов |
| Дуплекс | **полудуплекс**: общие shreg / bit_cnt / baud_cnt | лицензия владельца; ядро влезает только общим |

## Карта портов (дополнение к §5 базовой)

| Порт | R/W | Биты | Функция |
|---|---|---|---|
| `04h` | OUT | D7..D0 | **TXDATA**: старт кадра (параллельная загрузка из живых A-пинов T2). Приём запрещён при TXRDY=0/RXRDY=1 — байт отбрасывается (контракт ниже) |
| `04h` | IN | A7..A0 | **RXDATA**: принятый байт (из shreg[8:1]); чтение снимает RXRDY/IRQ |
| `05h` | IN | A0 | **RXRDY** (1 = байт ждёт в shreg) |
| `05h` | IN | A1 | **TXRDY** (1 = ядро в idle, кадр можно стартовать) |
| `05h` | IN | A7..A2 | 0 (резерв: A2 — FE, план Б) |

Чтение — тем же механизмом, что KBROW (03h): CPLD отдаёт байт на A-пины (AD0-7) в T2 при `rd_drive` — драйверы и мультиплекс уже есть, добавлены только селекторы.

## Архитектура полудуплексного ядра (п.26 шапки RTL)

Один набор счётчиков/сдвигов на TX и RX (одновременность исключена: старты разрешены только из idle):

```
shreg[9]     9 МЦ — {данные/байт RX, выход}: [0]->TX pin (IO-MC, INIT=1);
               TX-загрузка: {A[7:0], 1'b0} из живых A-пинов T2; сдвиги вправо с
               инжекцией '1' -> после кадра shreg сам приходит в все-'1' (idle
               по построению, как shreg 9h1FF txclient);
bit_cnt[4]   4 МЦ — 0..9 (0=idle/старт, 1..9=биты кадра) — общий;
baud_cnt[4]  4 МЦ — mod 13 свободным ходом; jam-фазировка при стартах
               (TX: <=0 — сдвиг №1 ровно через 13 тиков; RX: <=6 — выборка
               центра старт-бита на T+6, далее каждые 13);
rx_s0/rx_s1  2 МЦ — 2-ступенный синхронизатор входа RX (P38);
rx_run       1 МЦ — идёт приём; rx_start = спад rx_s1-vs-rx_s0 в idle;
rx_full      1 МЦ — RXRDY + IRQ RST 7.5 (P75); сброс — IN 04h;
tx_run       1 МЦ — идёт передача (TXRDY = ~tx_run);
adv_q/ld_q   2 МЦ — регистровые хелперы тика/конца кадра (наработка v8:
               декоды счётчиков вынуты из D-функций shreg).
Итого ядро: 24 МЦ; минус транзит −3 => прогноз фита 85−3+24(+0..2 хелпера
декодов io_wr_tx/io_rd_rx/io_rd_st) = **106..108/108 МЦ**, вх.ФБ ~190-200/216,
ПТ ~255-290/540, рег ~76-78, ноги 73/81 (+P75=rx_int, PGND 9→8).
```

RX-механика (уроки 01_timer): валидация старт-бита В ЕГО ЦЕНТРЕ (тик T+6:
`rx_s1=='0'` — иначе глитч, abort без порчи shreg), выборки битов строго в
центрах (T+13k+6), стоп-проверка на T+123 (bc=9): `rx_full := 1`. Без FE-флага в v1.

TX-механика (наработка txclient v8): загрузка в T2 записи порта — ОДИН такт,
байт берётся с живых A-пинов (тот же строб, что штатный `bus_reg <= A`); старт-бит
на шине С ТОГО ЖЕ такта (бит [0] загружен '0'); сдвиги по baud_tick bc=0..9
(10 бит ровно по 13 тиков); стоп-заполнение — инжекция '1' (константа):
после кадра shreg == все-'1' без отдельных загрузок.

## Контракт полудуплекса (для прошивки и ПК-стороны)

1. `OUT 04h` — только при TXRDY=1 (поллинг IN 05h.1; прецедент v3.10: буфер с
   TXRDY-поллингом даёт те же гарантии без потерь, период опроса << бита).
2. Запись в TX при активном RX/передаче — байт ТИХО ОТБРАСЫВАЕТСЯ (кадр не портится).
3. RX-байт прочитать (IN 04h) до следующего OUT 04h: чтение снимает RXRDY;
   новая загрузка TX перезапишет shreg.
4. Одновременный спад RX и запись TX в один такт — приоритет RX (TX-байт отброшен).
5. ПК-сторона: не слать байты во время кадров платы (двухпроводная линия
   электрически полнодуплексна, ядро — нет; коллизия = потеря байта RX).
6. Прошивка: IRQ RST 7.5 (фронт rx_full) — IN 04h в ISR снимает запрос;
   после EI не забыть SIM-разблокировку RST 7.5 (прецедент 01_timer).

## Чек-лист фита (владельцу, после прогона ISE)

1. `Fitting Status: Successful`, 0 ERROR; WARNING Cpld:897 — ожидаемы ≤1-2 (см. выше).
2. Ресурсы: МЦ ≤108 (прогноз 106-108), вх. ФБ ≤216 (прогноз ~190-200), ПТ ~255-290, рег 76-78, ноги 73/81.
3. **GSR**: «Global set/reset net(s) used» + «GSR : 1»; пин 1 = RST, буфер GSR/I;
   ядро UART в GSR-домене: shreg — SET-ветка (INIT=1, idle '1'), bit_cnt/baud_cnt/rx_*/tx_run/adv_q/ld_q — CLR;
   ВНЕ домена (бит-в-бит v3.9.3): por_sh×4/por_run/cnt×3/x1_n.
4. Транзит TX-старый исчез: sod_q/tx_pass/tx_q в .rpt НЕТ; `TX` = shreg[0] (IO-MC P39).
5. P75 = rx_int — выход (не PGND!); PGND = {P74,P76,P78,P79,P81,P95,P96,P98} — 8 шт;
   P73 (SID) — выход (транзит RX), в PGND быть не должна.
6. Литералы сброса в термах: RST ×1 (RESET_IN) + por_run ×2 (класс v3.9.3, `fit_literals.py`).
7. Строб io_wr_tx содержит !por_run (защита окна POR от floated-шины — класс v8).

## Статус

- **v4.0.0 (11-3): RTL + симуляции готовы, ждёт фита владельца в ISE** → .rpt на аудит
  по чек-листу выше → .jed и железо. ДО АУДИТА НЕ ШИТЬ (правило ветки hiclock).
- **Верификация: `scripts/sim_hwuart_v400.py` — 75/75 ПАСС** (цикл-точная модель
  NBA-семантики, полутакты x1_n): С1 POR/idle (TX='1' от INIT, RESET_IN, X1 7 тиков 5/7,
  SID-транзит, TXRDY) · С2 кадры 55h/AAh (**все переходы линии на сетке ровно 13 тиков,
  старт ровно 13** — jam=1 компенсирует лаг adv_q, PC-приёмник декодирует, shreg сам в
  idle 1FF) · С3 поток 3 байт с TXRDY-поллингом без потерь · С4 OUT при busy — байт тихо
  отброшен, кадр цел · С5 RX 55h: rx_full/фронт rx_int, статус RXRDY, IN 04h = байт,
  чтение гасит IRQ · С6 RX при активном TX игнорируется (полудуплекс), кадр TX цел ·
  С7 RST посреди TX- и RX-кадров: GSR гасит TX='1' в первый такт, ядро вычищено,
  приёмник жив после сброса · С8 глитч RX 3 тика — аборт в центре старта, инвариант
  bc==0 · С9 регрессия базы (порты 00-02h, KBROW 03h, writeback /WE ровно 2 тика,
  ПЗУ без /WE). `tb_hwuart_v400.v` — владельцу (iverilog): ключевые сценарии С1/С2/С3/С5/С7.
- Найдено и исправлено при верификации (в RTL и модели синхронно): jam TX-старта
  `baud_cnt <= 1` (НЕ 0: лаг adv_q 1 такт делал старт-бит 14 тиков = BREAK у приёмника);
  инвариант idle после глитч-аборта RX (bit_cnt <= 0 в ветке аборта).
- План Б (если МЦ не влезут, по возрастанию цены): (а) свернуть ld_q-класс декодов
  (декоды в 4 потребителя, −1 МЦ); (б) rx_s1 — 1 ступень синхронизатора (прецедент
  sod_q, −1 МЦ, риск метастабильности на 1,92 Мбод — только по результату фита);
  (в) FE-флаг статуса не вводить; (г) Collapsing Input Limit 28→18 по рецепту
  txclient М2 — на случай ERROR 892.
