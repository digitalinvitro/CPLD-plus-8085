## Архитектура (что добавлено, v3.3b3: 11 новых MC)

```
por_ce (X1 = 5 МГц, 1 такт clk / 200 нс, уже есть в дизайне)
   │  CE
   ▼
прескалер = txm_cnt[7:0] (УЖЕ ЕСТЬ: свободный счёт вверх от por_ce,
   в v3.2 он же — TX-маска; с v3.3b3 стоп в FF убран) ──обёртка 7Fh→80h──▶
   tmr_tick (комбинация) ──▶ tmr_tick_q (РЕГИСТР, 1 MC)
                                                                 │ 1 такт / 51,2 мкс
OUT 04h (T2, IOM, WR#=0) ──▶ bus_reg (уже есть) ──▶ tmr_load_q (РЕГИСТР, 1 MC)
                                                                 │
tmr_cnt[7:0] (8 MC): загрузка N из bus_reg, счёт вниз по тикам,
СТОП в 0 (enable = tmr_tick_q & !RST75_r), INIT/сброс = FFh
                                                                 │
RST75_r = (tmr_cnt == 0) — РЕГИСТР в МС выхода P75 (1 MC) ──▶ RST75 (P75)
```

Плюс 4 хранимых строба-хелпера `(* keep *)` (по 1 MC): `cpu_rst`, `al_cap`,
`bus_rd`, `wr_cap` — см. протокол v3.3b3 ниже.

- **Квант тика** = 256 × 200 нс = **51,2 мкс** (это строка «X1 5 МГц, k=8»
  из таблицы ANALYSIS.md §3).
- **Тик** = обёртка прескалера `7Fh→80h`: условие `tmr_tick = por_ce &
  (txm_cnt==7Fh)` захлопывается в **регистр tmr_tick_q** (1 такт clk) —
  декод 11 входов сидит в ОДНОЙ MC, а не размазан по 8 битам счётчика.
  Фаза та же, что у прежнего {tmr_hi, por_cnt}: 1-й тик через 128 por_ce
  после конца POR.
- **Счётчик** `tmr_cnt[7:0]`: параллельная загрузка N **из bus_reg** при
  `OUT 04h` (bus_reg захватывает A тем же фронтом, что seg_q; данные CPU
  держит до WR#↑ — дисциплина «последний сэмпл валиден» сохранена),
  декремент по тикам, **останов в нуле**.
- **Выход** `RST75` = регистр `RST75_r = (tmr_cnt==0)`: **фронт** защёлкивается
  CPU как RST 7.5 (вектор 003Ch), маска SIM M7.5, защёлка чистится при
  обслуживании или `SIM` R7.5. Регистр на выходе — ещё и без комбинационного
  глитча декода нуля на ноге.
- Прескалер свободный (без сброса — период 2^k от фазы не зависит);
  INIT `tmr_cnt = FFh` → после RESET **нет ложного фронта** (RST75=0), а
  без записи счёт дойдёт до нуля за 255 тиков (~13,1 мс) — CPU в этот момент
  держит маску RST 7.5 (даташит), так что прерывания не будет до снятия
  маски программой.

## Отличия от ANALYSIS.md (и почему)

| # | В анализе | В реализации | Почему |
|---|-----------|--------------|--------|
| 1 | квант 102,4 мкс от **CLKOUT** (P83) | квант **51,2 мкс от внутреннего por_ce** (X1) | фронт CLKOUT приходит через ~30–120 нс (t_d CPU) после фронта X1 → сэмплирование пина в 25 МГц домене = гонка выборки; клок от пина = PT-клок. Оба варианта запрещены дисциплиной проекта (один домен 25 МГц, без edge-детекторов и PT-клоков). Сэмплер CLKOUT — это ещё +1 MC: 9+8+1 = 18 > 17 свободных |
| 2 | автоперезагрузка при нуле | **ре-арм из ISR** (`OUT 04h`) | автоперезагрузка требует 8-битный регистр значения (+8 MC → 25 > 17); bus_reg непригоден — переписывается каждым циклом чтения памяти. Ре-арм = `MVI A,N / OUT 04h` в ISR, джиттер ~5 мкс на период ~10 мс |
| 3 | период = (N+1) × квант | период = **N × квант** | счётчик останавливается в 0, повторная загрузка того же N даёт ровно N тиков между фронтами |

50 Гц при этом достигается: **N=195** (тик 9,984 мс) + **деление на 2 в ISR**
→ 19,968 мс — ровно те же 19,968 мс, что давал N=194 × 102,4 мкс из анализа.

## Софт-интерфейс

Порт **04h** (запись): N = период в тиках. `T = N × 51,2 мкс`
(N=1..255 → 51,2 мкс … 13,05 мс; N=0 = стоп).

```
TMR_N    EQU 195            ; 195 x 51,2 мкс = 9,984 мс; /2 в ISR = 19,968 мс ~ 50 Гц
TMRPORT  EQU 04h
...
      MVI  A, TMR_N
      OUT  TMRPORT          ; загрузить N и запустить (первый тик через ~10 мс)
      MVI  A, 00011000b     ; MSE=1, M7.5=0 (НЕ маскировать 7.5), 6.5/5.5 маскированы
      SIM
      EI                    ; вектор RST 7.5 = 003Ch
      ...
; ---- ISR (адрес 003Ch) ----
ISR:  PUSH PSW
      LDA  TICKS            ; программное деление на 2: действие каждые 2 тика
      XRI  01h
      STA  TICKS
      ANI  01h
      JNZ  ISR_DONE         ; нечётный тик — выйти
      ...                   ; чётный тик: работа 50 Гц (дисплей/часы)
ISR_DONE:
      MVI  A, TMR_N
      OUT  TMRPORT          ; РЕ-АРМ (обязательно! автоперезагрузки нет)
      POP PSW
      EI
      RET
```

Замечания:
- RESET IN ставит маску RST 7.5 — после сброса прерываний нет, пока
  программа не выполнит SIM (снять маску) и EI;
- защёлка RST 7.5 помнит фронт даже при маске: пропущенный на DI-участке
  тик «догонит» одним прерыванием после снятия маски;
- счётчик после сброса = FFh → без записи единственный фронт через ~13,1 мс
  и потом стоп (ре-арма нет) — программа обязана сделать `OUT 04h` в
  инициализации, если таймер нужен;
- ISR обязан ре-армиться (`OUT 04h`) и завершаться EI — классика 8085;
- изменение N на лету допустимо (следующий период уже с новым N).

## Тест-прошивка ПЗУ (rom/)

**Звук или мигание?** Рекомендация: **звук** — показательнее. Тон — это сотни
прерываний в секунду: любой сбой (залипание счётчика, потеря ре-арма, срыв ISR)
слышен мгновенно, а кратность кванта проверяется высотой тона (вдвое медленный
прескалер = тон на октаву ниже). Мигание сегмента — удобный фоновый визуальный
контроль, но 1 Гц скрывает пропуски отдельных тиков. Поэтому **основной образ
делает оба**: тон — главный индикатор, мигание — «секундный маяк» и заодно
проверка дисплея. Для тихих сессий есть отдельный blink-only образ.

### Как это работает

- **Тон.** N = 20 → период 20 × 51,2 мкс = 1,024 мс; ISR инвертирует D4 (SND)
  → меандр. Частота НЕ ровно 488 Гц, а **~470 Гц**: к кванту добавляются
  накладные входа в ISR и ре-арма (~40 мкс, тело ISR до ре-арма ~91 такт ≈ 36 мкс +
  квитанция прерывания) — это норма. Если тон ~230 Гц (на октаву ниже) —
  квант 102,4 мкс вместо 51,2, дефект прескалера HDL.
- **Мигание.** Каскадный счётчик 116 × 4 = 464 прерывания ≈ 0,49 с на
  полупериод → цикл ~1 с. Инвертируется сегмент 'g' (средняя черта) на всех
  4 разрядах; dp горит постоянно — маячок «дисплей жив». Индикация статическая
  (все разряды сразу) — нагрузка заведомо меньше INIT «8.».
- **Регистр B:C — счётчик мигания, живёт между прерываниями.** Поэтому в ISR
  НЕТ PUSH B/POP B (урок v2, см. протокол дефекта ниже): POP B каждую квитанцию
  возвращал счётчику исходные 4:116, и он никогда не досчитывал до нуля.
  Сохраняется только PSW — ISR портит лишь A и флаги; вложенных прерываний
  нет (8085 запрещает IE на входе в ISR, EI только в конце).
- **MAIN:** LXI SP,FFFFh → порты (SEG=C0h, DIG=0Fh) → `OUT 04h` (запуск) →
  `SIM 1Bh` (маскировать 5.5/6.5, РАЗРЕШИТЬ 7.5; бит R7.5 = 0 — латч не трогаем,
  ложных фронтов до EI нет: после POR CPLD счётчик стоит в нуле и первого
  фронта RST 7.5 ещё не было) → EI → HLT-цикл:
  процессор спит между прерываниями, нагрузка ~5 %.
- **Векторы:** 0000h → JMP 0080h (MAIN); 003Ch → JMP 0040h (ISR). Свободные
  адреса заполнены 00h (NOP), а не FFh (FF = RST 7 — опасно при исполнении).
- **ISR обязан ре-армиться** (`OUT 04h`) — автоперезагрузки нет (стоп в нуле);
  копии регистров SEG/DIG держатся в ОЗУ 8000h/8001h (порт 01h перезаписывает
  весь байт).

### Протокол дефекта v1 → v2 (PUSH B/POP B против счётчика мигания)

- **Симптом на железе (первая прошивка v1):** тон есть, таймер/RST 7.5/ре-арм
  работают, но мигания нет — на дисплее постоянно горят сегменты 'g' и dp
  (SEG = C0h, маячок MAIN не переключается).
- **Диагноз:** в ISR стояли `PUSH B` (вход) и `POP B` (выход). Счётчик мигания
  живёт в B:C и ОБЯЗАН переживать прерывания, но `POP B` каждую квитанцию
  восстанавливал со стека исходные KB:KA = 4:116: `DCR C` делал 116→115,
  а POP возвращал 116. Ноль не достигался никогда → ветка
  `LDA SEGST / XRI 40h / STA / OUT 00h` не выполнялась ни разу (мёртвый код).
  Тон при этом работал: ветка тона B:C не трогает.
- **Лекарство v2:** PUSH B/POP B убраны. B:C выделены ISR (инициализация один
  раз в MAIN — `LXI B,KB*256+KA`; вложенных прерываний нет — 8085 запрещает IE
  на входе в ISR, EI только в конце, B:C больше никто не трогает). Сохраняется
  один PSW. Побочный выигрыш: ISR короче на 22 такта (PUSH B 12 + POP B 10) —
  тон поднялся с ~465 до ~470 Гц, накладные снизились с ~55 до ~40 мкс.
- **Проверка:** программная эмуляция каскада — ровно 464 прерывания между
  инверсиями, период стабилен; оба образа побайтово совпали с обновлённым
  ручным эталоном (verify_hex.py: checksum + эталон + контрольные точки
  0041h=3Ah «нет C5», 0065h=F1h «нет C1»); размер прежний — 160 байт
  (0000h–009Fh), т.к. MAIN стоит на фиксированном ORG 0080h.
- **10-23, только комментарий:** уточнён текст комментария к `SIMW EQU 1Bh`:
  в 1Bh бит R7.5 = 1 — латч RST 7.5 СБРАСЫВАЕТСЯ (раньше комментарий
  утверждал «латч не трогаем»; на поведение и байты не влияло — образы
  пересобраны, hex не изменились, эталоны сошлись).

### Осциллограмма v2 (SND_magnify, 250 мкс/дел): форма сигнала и «нечистый» тон

- Замер владельца на прошивке **v2** (мигание работает — само по себе признак
  v2: в v1 ветка мигания была мёртвым кодом и физически не могла мигать).
  Счётчик DSO: **493,024 Гц**; независимо по сетке экрана: период
  203 px × 10 мкс/px = 2030 мкс → 492,6 Гц — счётчик подтверждён (сетка
  12 дел × 25 px, запись 3,0 мс; калибровка px/дел сошлась с частотомером
  до 0,1%).
- **Форма: меандр 50/50** (включённая половина 1020 мкс, выключенная
  1010 мкс) — SND инвертируется каждое прерывание, период прерываний
  ~1,01 мс. «Тик» мигания (+9 мкс раз в 464 прерывания) на экране 3 мс
  не виден — как и предсказано.
- **BUZZER1 — активный излучатель** (SCHEMATIC §6/§7.6, BUZZER-12X9): SND не
  «играет» тон, а включает/выключает питание модуля. На осциллограмме щуп
  стоит на R4 (100 Ом) = ток излучателя: включено — пьедестал ~300 мВ
  (~3 мА, средний потребляемый ток) + узкие пики до ~490 мВ (~4,9 мА) с
  шагом ~106 мкс (~9,4 кГц пиков; для квадратного возбуждения собственная
  частота излучателя ~4,7 кГц) — работает его ВНУТРЕННИЙ генератор;
  выключено — 0 мА (мелкие выбросы до −164 мВ — разряд ёмкостей после
  выключения).
- **«Нечистый» тон — свойство активного излучателя при жёстком гейтинге**,
  не дефект таймера/прошивки/CPLD: слышен собственный резкий тон модуля
  (~4–5 кГц), промодулированный стробом 493 Гц, а не чистая синусоида 493 Гц.
- **Следствие для методики:** высоту строба слухом не оценить — слух слышит
  излучатель, а не частоту прерываний. Частотный оракул — счётчик частоты
  DSO или период по сетке (оба согласуются выше — расхождение 0,1%).
- **Частота 493,024 Гц снова ВЫШЕ потолка 488,3 Гц** (модель «период = N
  тиков» даже при нулевых накладных) → модель «(N−1) тик + накладные»
  подтверждена и на v2 (на v1 было 494,01 Гц). Ожидание для v2 ~496 Гц
  (ISR короче v1 на 12 тактов до ре-арма), измерено 493,0 — расхождение
  ~0,7% в пределах точности счётчика DSO на пиковом сигнале (уровень
  срабатывания сидит в зоне пиков, точка пересечения гуляет). Разделительный
  тест кванта — `timer_test_n10.hex`: **~995 Гц ((N−1)) vs ~903 Гц (N)** —
  счётчик различит однозначно.

### Излучатель: 10-24 — BUZZER1 заменён на пассивный

Владелец подтвердил предыдущий вывод и пошёл дальше: BUZZER1 действительно
был **активным** излучателем (что и объясняло «нечистый» тон выше), и он
**заменил его на пассивный**. Результат: тон стал чище — теперь форму и
высоту звука определяет строб SND от программы (как и задумано в
MEMORY_MAP: «пассивный зуммер — тон генерирует программу»), а не внутренний
генератор модуля.

Осталась особенность: **выброс индуктивности в начале фронта** — глитч,
слышимый в начале тона. Причина: излучатель висит на ноге CPLD напрямую
(токоограничивающий R4 100 Ом стоит только на землю), при переключении SND
фронт бьёт в индуктивность/ёмкость излучателя без демпфирования — выброс
звенит и слышен как щелчок в начале каждого фронта тона. CPLD (24 мА
драйв) выброс переживает, но на звук он выходит.

Кандидаты-лекарства (по возрастанию вмешательства в плату):

1. Последовательный резистор в цепь SND (100–470 Ом между CPLD и
   излучателем): гасит выброс и звон, снижает громкость; самый дешёвый
   эксперимент.
2. Снаббер RC параллельно излучателю (для магнитного типа).
3. Встречно-параллельный диод (клемп выброса при индуктивной нагрузке).

Пока опыт ставится на одной плате — пометка в SCHEMATIC §7.6 оставлена с
примечанием о замене. Для тестов таймера/UART это ни на что не влияет
(SND в них не используется).

## Уточнение модели кванта: период = РОВНО N тиков, Q ≈ 50,7 мкс (10-23)

Анализ HDL v3.3b3 (`top_suart.v`) закрыл вопрос «(N−1) против N»:

- декремент `tmr_cnt` идёт **только** по тикам (`tmr_tick_q & !RST75_r`);
- загрузка N (`tmr_load_q`) имеет **приоритет** над декрементом;
- при ре-арме **раньше следующего тика** (Δ < Q — у v2 Δ ≈ 40 мкс < 51,2)
  тик не теряется: первый декремент после загрузки — на ближайшей сетке
  тиков, ноль достигается через ровно N тиков после фронта.

Следствие: **период фронтов RST 7.5 = N × Q точно; накладные ISR в период
НЕ входят** (сетка тиков свободно-бежащая). Модель «(N−1) тик + накладные»
(записана по замерам 10-22/10-23) была альтернативной подгонкой той же
кривой в предположении Q = 51,2 мкс — Verilog её исключает.

Тогда замер 493,024 Гц при N=20 означает:
**Q = 1014,2 мкс / 20 = 50,71 мкс → clk = 1280/Q ≈ 25,24 МГц** — «сверчок»
LTC6905 идёт на ~+1% от номинальных 25,000 МГц (в пределах допуска
семейства; прежний замер «25,00 МГц» был округлён). Замер v1 (494,01 Гц)
даёт Q = 50,61 мкс (clk ≈ 25,29 МГц) — обе читки согласуются с учётом
заявленной погрешности счётчика DSO на пиковом сигнале (±0,7%).

Разделительный тест `timer_test_n10.hex` (N=10): предсказание **~986 Гц**
(модели «N тиков, Q ≈ 50,7» и «(N−1)+накладные» дают 986–998 Гц — счётчиком
DSO почти неразличимы; наивная «N×51,2+накладные» давала бы ~903 Гц —
исключается). Однозначный арбитр — частотомер на **CLKOUT** (U3.37):
ожидаются ~2,52 МГц против номинальных 2,50.

Следствия для расчётов: рабочий тон N=20 — фактические **~493 Гц** (таблица
выше писала ~470 по модели с накладными); 50 Гц при делении на 2 в ISR —
**N=197** (197 × 50,71 мкс = 9,99 мс → 50,05 Гц), а не 195/196.

## Тест-прошивка UART: таймер как задатчик бодрейта (10-23)

Задание владельца: практическое применение таймера — формировать битовые
интервалы UART прерываниями, а не калиброванными циклами, и оценить,
насколько это упрощает/удорожает код против полностью софтверного варианта.

**Тракт передачи** (PORTS_MAP §8, Task 70-a): CPU.SOD (запись через SIM) →
CPLD P72 → P39 (прозрачный транзит; TX-маска держит '1' 51,2 мкс после
сброса — BREAK невозможен, но прошивка и сама ставит SOD=1 первым делом) →
CH340G.RXD (U6.2) → USB → виртуальный COM-порт ПК. Приём (на будущее):
CH340G.TXD → CPLD RX → SID (RIM 20h).

### Как работает timer_test_uart (v4: 207 байт, 0000h–00CEh)

- **Одно прерывание RST 7.5 = один бит.** Период прерываний = ровно N×Q
  (см. «Уточнение модели кванта»; ре-арм — первое действие ISR, код стоит
  прямо в векторе 003Ch: `MVI A,N / OUT 04h`, ~13 мкс от фронта — тик не
  теряется, а выход SOD лишь сдвинут на постоянную добавку: старт/стоп
  ~+23 мкс, данные ~+35 мкс от фронта тика).
- **Фазы кадра в регистре C**: 0Bh = кадр загружен → 0Ah = старт-бит
  (**+ загрузка байта в D из (HL)**) → 09h..02h = данные d0..d7 (LSB-first,
  единицы втягиваются сверху) → 01h = стоп-бит **+ проверка конца строки**
  → **0Ch = холостой бит (2-й стоп; v4)** → 0Bh = старт следующего.
  Символ = 11 фронтов (10 кадра 8N1 + 1 холостой), фаза 00h не возникает —
  стоп-фаза перезаряжает счётчик сама. Вне кадра D=0FFh — фиксированная
  точка пути данных: холостой бит прокатывается через него, ничего не меняя
  (SOD=1), поэтому отдельной ветки для него в ISR нет.
- **Регистры ISR**: C фаза, D сдвиговый, E счётчик паузы, HL указатель
  сообщения; MAIN живёт в HLT и их не трогает — сохранять нечего (урок v2
  в обратную сторону: выделяй ISR регистры, а не воюй с PUSH/POP).
- **MAIN**: SOD=1 (гасим возможный BREAK) → дисплей «....» (dp на всех
  разрядах, маячок «стартовала» — отличим от v2-тона 'g'+dp) → пуск
  таймера → SIM 1Bh → EI → HLT. Нагрузка CPU ~10% (ISR ~50 мкс из ~406).
- Вывод: `TIMER-UART OK` + CR LF, пауза ~14 бит, повтор (~14 строк/с,
  177 фронтов ≈ 72 мс).

### Скорости (бит = N×Q)

|---|---|---|---|
| 2 | 101,3–102,4 мкс | 9770–9870 | 9600 |
| 4 | 202,6–204,8 мкс | 4883–4936 | 4800 |
| **8 (по умолчанию)** | 405,2–409,6 мкс | 2441–2468 | 2400 |
| 16 | 810,4–819,2 мкс | 1221–1234 | 1200 |

Ошибка +1,7..+2,8% (доля «сверчка» + квантование) неустранима квантом —
и именно она выстрелила в первом прогоне (см. ниже). Выборка середины
бита тут не при чём: дрейф за 9,5 бит ≤ 26% бита при лимите ~50%; опасна
была коллизия ГРАНИЦЫ кадра, закрытая холостым битом (2 стоп-битами).
Если мусор остался и с v4 — источник не в скорости: прошить

### Прогон на железе 10-23: мусор сериями → фикс (2-й стоп-бит)

Первый образ (кадры ВПЛОТНУЮ, 10 фронтов/символ) на терминале 2400 давал
~25% строк с мусором СЕРИЯМИ по 6–8 символов в середине строки, мусор
повторялся байт в байт (`TIMQЄ©IQЃOK`, `TIMER-UA*z-5`, потерянные CRLF —
строки склеивались). Это подпись **сдвига на 1 бит в непрерывном потоке**:
приёмник, потеряв бит, «пережёвывает» хвост строки до паузы, где
ресинхронизируется — поэтому следующий столбец/строка снова чистые.

**Механизм:** TX = 2465 бод (+2,7%). При кадрах вплотную следующий
старт-фронт приходит через 10 бит TX = **9,74 бита приёмника 2400 — на
26% бита РАНЬШЕ конца его кадра**: приёмник обязан ловить старт, ещё
«вися» в кадре, и в плохой фазе (набег 0,27 бита/кадр) периодически
промахивается → сдвиг на 1 бит → серия мусора. Детерминизм дампа —
биение фазы приёма против фиксированной строки.

**Фикс v4:** один холостой бит между кадрами = классические 2 стоп-бита:
следующий старт = 11 бит TX = **10,71 бита приёмника — ПОСЛЕ конца его
кадра** (+0,71 бита): коллизия исчезает, ошибка скорости гасится запасом
стоп-времени. Бонус: одиночный сбой отныне портит ≤ 1 символ (ресинхрон
на каждом реальном старте), а не хвост строки. Стоимость: −2 байта образа
(209→207: preload'ы D убраны — загрузка переехала в старт-фазу) и −10%
пропускной способности. Софт-референс НЕ правился: у него +0,8%, след.
старт приходит на 8 мкс позже конца кадра приёмника — коллизии нет.

### Прогон v4 на железе 10-24: ПАСС

Владелец: «тест работает замечательно, текст ровный» — поток «TIMER-UART OK»
без мусора на терминале 2400 8N1. Диагноз коллизии границы кадра и фикс
(2-й стоп-бит) подтверждены; расчёт запаса (+0,71 бита между кадрами)

**приём** (CH340G.TXD → RX → SID, RIM 20h): тест приёма-передачи (эхо).

### Сравнение с полностью софтверным формированием

бода (0,03% при 2,5 МГц; при фактических ~2,52 МГц → 2419 бод, +0,8%).

| Код+данные без заполнения | ~150 байт | ~111 байт |

даже экономнее; для всего остального (монитор, приём, фоновой дисплей) —

## Тест UART приём-передача: эхо (10-24)

После ПАССА TX-теста (v4) — первый тест тракта **приёма**. Задание
владельца: полноценный UART. Формат — ЭХО: символ, набранный в терминале,
возвращается на экран. И приём, и передача тактируются таймером
(1 прерывание = 1 бит). **CPLD НЕ МЕНЯЛСЯ** — тот же фит v3.3b3: транзиты
RX→SID и SOD→TX уже есть, шьётся только ПЗУ.

Тракты: передача — как в TX-тесте (SIM → SOD → P72 → P39 → CH340G → COM);
приём — CH340G.TXD → CPLD RX (P38) → транзит → CPU.SID (P73), чтение
**RIM 20h** (бит 7 аккумулятора).

### Как работает uart_echo_test (229 байт, 0000h–00E4h)

- **MAIN опрашивает SID в цикле с DI** (`RIM / ANI 80h / JNZ POLL`,
  ~10 мкс на итерацию — латентность обнаружения старта ≤ 10 мкс).
  DI в опросе — принципиально: ISR «не залетают под руку», а любой
  фронт сетки, сработавший под DI, ловится латчем RST 7.5 и выбрасывается
  при арме (см. ниже). Пока MAIN в опросе — TX-движок стоит (кадры к
  этому моменту уже закончились).
- **Атомарный арм приёма** (старт-бит пойман):
  1. `MVI A,RXN1 / OUT 04h` — загрузка **12 квантов (= 1,5 бита)** в
     таймер; загрузка даёт фронт через (N−1)..N квантов (фаза
     прескалера) → первая выборка в середине d0 (окно ±208 мкс, запас
     ≥ 130 мкс по модели);
  2. `MVI A,08h / SIM` — сброс латча RST 7.5 **ПОСЛЕ загрузки**:
     залетевший фронт мог сработать только до этой точки (после загрузки
     новый фронт ≥ 11 квантов) — выбрасывается атомарно, **гонка
     исключена**;
  3. `L=0, H=11, EI` — кадр приёма = **11 интервалов**: 12Q (выборка d0)
     + 8×8Q (d1..d7) + 3×8Q (хвост).
- **RX-автомат в ISR** (регистры H/L): ре-арм в векторе 003Ch держит
  сетку 8 квантов = 1 бит; при H≥4 — выборка (`RIM / ANI 80h / RAR /
  MOV A,L / RAR / MOV L,A` — биты LSB-first втягиваются в L сверху),
  H=3..1 — хвост без выборки, H→0 — **релиз**: если TX свободен
  (C=0FFh) — `MOV D,L / MVI C,0Bh` (эхо стартует следующим фронтом),
  иначе байт отбрасывается (v1 без очереди TX).
- **TX-автомат** — тот же, что в v4 (фазы в C, сдвиговый D, путь данных
  RRC/ANI/ORI/SIM), но **однобайтовый**: стоп-фаза сразу уводит в покой
  (C=0FFh) — 2-й стоп-бит не нужен, кадры далеко друг от друга.
- **Приоритет RX над TX**: вентиль в начале ISR — при H>0 TX-автомат не
  двигается (SOD держит уровень, «заморозка кадра»). При печати за руку
  недостижимо (эхо кончается через ~5 мс после символа); при вставке
  даёт артефакты (ниже).
- **Дрейф выборки**: сетка 8 квантов = 405,7..409,6 мкс против бита
  терминала 416,67 — выборка уезжает на ~7–11 мкс РАНЬШЕ на бит; к d7
  ~72 мкс раньше центра — лимит ±208 мкс, запас > 130 мкс (модель).
- **Хвост 3 интервала (~3 бита) — урок v4 зеркально**: эхо-старт выходит
  на линию только после конца кадра приёмника ПКА (10 бит от ЕГО старта)
  с запасом ~+2,15 бита (модель); без хвоста эхо-старт попадал в
  стоп-бит кадра ПКА — та же коллизия границы кадра, что дала мусор
  сериями в TX-тесте, только в обратную сторону.
- **Баннер**: один символ '>' сразу после сброса (тот же TX-автомат) —
  виден в терминале ~5 мс после RESET, признак «прошивка жива».
  Дисплей: **«8.» на всех 4 разрядах** — маячок (отличим от «....»
  TX-теста v4 и от «g.» тона v2).
- Регистры ISR: C фаза TX, D сдвиговый TX, H интервалы RX, L накопитель
  RX; B, E свободны. MAIN не держит в регистрах ничего долгоживущего.

### Модель (scripts/uart/sim_uart_echo.py)

Событийная модель всего тракта: ПКА шлёт на ровно 2400 бод → приёмник
ПКА декодирует эхо с ресинхом по старт-фронту. Таймер моделирован по
HDL v3.3b3 (сетка тиков свободно-бежащая, загрузка даёт фронт через
(N−1)..N квантов, ре-арм из ISR — цепочка точная). Результат:
эхо = баннер + 'AZ5 az19!' на **400 свипах** фазы прескалера и
латентности опроса; минимальный запас выборки середины бита **130,4 мкс**
(лимит 208,3); минимальный запас эхо-старта **+2,15 бита** после конца
кадра ПКА; гонка латча не воспроизводится ни в одной точке свипа.
Стресс «paste» (3 мс между символами): потери ожидаемы (v1 без очереди,
MAIN не опрашивает линию во время чужого кадра) — задокументировано, не
дефект.

### Ограничения v1 (задокументированы, не дефекты)

- **Вставка (paste) блока текста** — потери/мусор: нет очереди TX и
  опрос линии останавливается на время чужого кадра. Печатать по одному
  символу — эхо чистое. Очередь/фоновый буфер — кандидат в v2.
- Символ, набранный во время баннера (первые ~5 мс после сброса),
  теряется.
- Байт отбрасывается, если в момент конца приёма TX ещё занят.
- Скорости: гарантирован дефолт N=8 (2400) и N=16 (1200); 4800/9600 —
  на пределе (аддеры ISR ~30–40 мкс = 15–40% бита): возможны
  эксперименты `-D TMR_N=4/2`, но без гарантий.

### Диагностический вариант эха: uart_echo_diag (10-24)

**Ситуация:** на железе баннер '>' пришёл, но эха нет — вводимые символы
не возвращаются. TX-тракт тем самым доказан, а приём PC→плата
(CH340G.TXD → P38 → транзит → SID → RIM) упражняется **впервые**.
Сверка «на бумаге» сомнений не дала: в фите v3.3b3 транзит есть
(`SID <= RX`, RX = вход P38, SID = выход P73), медь платы сходится
с нетлистом (цепь «TX»: U6.2 → U1.38; цепь CPU17: U3.5 ↔ U1.73).
Поэтому сделан диагностический образ: логика эха НЕ тронута, на дисплей
выведен индикатор приёма — видно, ДОХОДИТ ли ввод и ГДЕ рвётся.

**Дисплей (после RESET «0.0.0.0.» — маячок старта):**

- одна пара разрядов — **счётчик пойманных старт-битов** (hex, mod 256):
  растёт на 1 при каждом нажатии клавиши;
- вторая пара — **последний принятый байт** (hex).

Мультиплексия — в MAIN, шаг на каждый цикл опроса (4 фазы, ~610 Гц на
разряд — без мерцания). DMUX портит только A/флаги (HL сохраняется
PUSH/POP; B/C/D/E не трогаются; ISR в покое тоже трогает лишь A) —
взаимных порчей с ISR нет. Цена: ~55 мкс к латентности ловли старта
(окно выборки d0 ±208 мкс; симуляция с периодом опроса 185 тактов
вместо 25 — ПАСС, запасы прежние: выборка 130,4 мкс, эхо-старт +2,16 бита).

**Чтение результатов (вводить по одному символу):**

| Дисплей / поведение | Вывод |
|---|---|
| '>' есть, счётчик НЕ тикает, байт 00 | приём мёртв ДО автоматики: (а) **flow control в терминале** (RTS/CTS или XON/XOFF) — выключить: модемные линии CH340G (U6.9–15) на плате не разведены, CTS терминал не дождётся и молча придержит ввод — баннер при этом приходит как ни в чём не бывало; (б) обрыв CH340G.TXD (U6.2) → P38; (в) контакт ножки 5 (SID) в ZIF U3 / дефект 1821ВМ85 по SID. Осциллограф: кадры при вводе на P38 и U3.5 |
| счётчик ТИКАЕТ, байт неверный (FFh/мусор) | старт ловится, биты читаются мимо сетки: сверить 2400 8N1 терминала; форма P38 осциллографом |
| счётчик ТИКАЕТ, байт ВЕРНЫЙ, эха НЕТ | приём исправен ЦЕЛИКОМ (до RIM и сетка выборки); вопрос к релизу эха (маловероятно — логика релиза не менялась) |
| счётчик МЧИТСЯ сам, байт 00, без ввода | линия RX прижата к 0 (КЗ/мёртвый CH340G): MAIN ловит «старты» непрерывно |

Отличия от v1 по листингу: +4 байта в релизе ISR (`MOV A,L / STA 8001h` —
копия байта на дисплей, пишется даже при уроне эха), `CALL DMUX` перед
`DI` и `INR B` после `SIM` в MAIN, блок DMUX/HSEG с 00F0h, таблица
SEGTAB с 0150h (lo = 50h — `ADD L` без переноса). Верификация:
check_diag_hex.py — векторы и ISR 0000h–008Fh совпали с v1 байт в байт
(кроме 2 адресов переходов на RXE: 0099h → 009Dh), все вставки и
DMUX/SEGTAB — по контрольным точкам.

### diag v2 — биты хвоста: вердикт по кейсу «счётчик тикает, эха нет, редкая 'ю'» (10-24)

**Отчёт владельца по diag v1:** счётчик старт-битов ТИКАЕТ на каждое
нажатие; эхо в терминале почти всегда НЕВИДИМО; изредка (единичные
случаи) выходит буква **'ю'** (CP1251, байт 0FEh). Софт-UART монитора
на той же меди работал полностью.

**Что из этого уже следует (без новой прошивки):**

- счётчик тикает ⇒ старт-биты доходят до MAIN (RIM/SID живы), flow
  control терминала ИСКЛЮЧЁН — при придержанном вводе счётчик молчал бы;
- 'ю' дошла до терминала ⇒ конвейер релиза и эха (релиз RX → TX-автомат
  → SOD → CH340G → COM) РАБОТАЕТ ЦЕЛИКОМ: терминал показал именно то,
  что плата приняла. Вопрос только в ЗНАЧЕНИИ принятого байта: почти
  всегда он «невидимый» (00h–1Fh), изредка 0FEh;
- сигнатурная модель (scripts/uart/sim_rx_signature.py): при ЧЕСТНЫХ
  2400 8N1 приём даёт байт = коду клавиши на ЛЮБОЙ фазе прескалера и
  латентности опроса (1000/1000 прогонов, запас ≥ 130 мкс) — мусор
  невозможен. Следовательно, ИСТОЧНИК шлёт НЕ на 2400.

**Сигнатуры** (наш RX 2400 ← терминал X бод; свип фазы/латентности):

| Терминал шлёт | 'a' (61h) | 'b' (62h) | 'o' (6Fh) / '?' (3Fh) | Enter (0Dh) | E, хвост |
|---|---|---|---|---|---|
| **2400 (норма)** | 61 | 62 | 6F / 3F | 0D | 7 |
| **~1200 (вдвое медленнее)** | **06 (невид.)** | **18 (невид.)** | **0FEh = 'ю'** | E6 = 'ж' | 0–4 |
| ~4800 (профиль fw_mon **v5**!) | F4/FC | F4/FC | F5–FD | F1–F9 | 7 |
| ~9600 | FF/FE | FF/FE | FF/FE | FE | 7 |

Картина владельца («байт почти всегда невидимый + изредка 'ю'»)
совпадает ТОЛЬКО со строкой **~1200**. Напоминание: монитор fw_mon
v5 работает на **4800 8N1** (MEMORY_MAP, §ПЗУ), старый fw_mon v1 — на
2400; профиль терминала, «привычный» по монитору, для эхо-теста не
годится — нужен тот же профиль, при котором TX-тест дал «ровный текст»
(**2400 8N1**).

**diag v2** делает вердикт видимым одним нажатием: интервалы хвоста
(H=3..1), как и данные, читают линию — ISR пишет SID в E (MSB-first:
E = t1<<2 + t2<<1 + t3); при чистой сетке хвост ложится на стоп/idle,
то есть **E = 7**; E < 7 — сетка уползла (биты хвоста поймали данные).
Дисплей: **[счётчик mod 16][E][байт]**, после RESET «0.0.0.0.».

Критичный путь приёма НЕ тронут: вектор ре-арма 003Ch–003Fh и выборки
d0..d7 (0083h–0089h) = v1 байт в байт (check_diag2_hex.py; отличия —
операнды JMP MAIN/JZ RXE/JM и блоки вставок: JMP RXDCR 008Ah, RXTAIL
008Dh–0093h; MAIN с 00B0h, DMUX с 0100h, SEGTAB с 0160h).

**Чтение diag v2** (вводить по одному символу, начать с 'a' ×3):

| Дисплей на 'a' | Вывод |
|---|---|
| x1 / 07 / 61 | приём на 2400 исправен целиком — эхо обязано быть видимым; сообщить, что в терминале |
| x1 / 00–04 / 06 | терминал шлёт ~1200 — **выставить 2400 8N1** |
| x1 / 07 / F4–FC | терминал шлёт ~4800 (профиль монитора v5) — **выставить 2400 8N1** |
| x1 / 07 / FE–FF | терминал шлёт ~9600 — **выставить 2400 8N1** |
| x1 / E<7 / 61 | сетка уползает к концу кадра — сообщить код E |

После выставления 2400 8N1 ожидание: **x1 / 07 / 61** и 'a' в терминале
(~5 мс). Затем Enter → 0D/07 и Enter в терминале.

## Как собрать

1. В ISE-проекте **beta** (отдельная копия проекта или замена источника):
   `beta/01_timer/top_suart.v` — Set as Top Module; UCF —
   `beta/01_timer/top_suart.ucf`.
2. Опции те же, что у стабильного: Translate: Keep User Location
   Constraints = ON; Place & Route: Ground on Unused IOs = ON; XST: Keep
   Unused Inputs = ON. (План Б, если не ляжет: Fit Properties → Collapsing
   Input Limit = 20.)
3. (Желательно) ISim: `tb/timer_tb.v` + `top_suart.v` — все проверки T0..T5
   должны дать «ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ».
4. Фит → чек-лист .rpt (ниже) → .jed в плату → тест на железе.

## Чек-лист .rpt (beta/01_timer v3.3b3, поверх стабильного)

- **Fitting Status: SUCCESSFUL**, 0 ERROR, сирот нет;
- **WARNING Cpld:897 = 0** — НИ ОДНОГО BUFR: bus_reg<1..5,7> и seg_q<0>
  сидят В СВОИХ пиновых МС (уравнения захвата 4–7 входов);
- PGND = **ровно {P74, P76, P78, P79, P81, P95, P96, P98} — 8 шт** (P75
  вышла — стала выходом RST75);
- **RST75 = P75**, выход, FAST; RST75_r — регистр в МС выхода (входы:
  tmr_cnt[7:0] + cpu_rst);
- Equations: `tmr_cnt` 8 бит (enable `tmr_tick_q & !RST75_r`, загрузка
  `tmr_load_q` из bus_reg); `tmr_tick_q` — регистр (por_ce & txm_cnt==7Fh);
  **txm_cnt — свободный счёт вверх (стопа в FF НЕТ)**; `txm_mask_q` —
  регистр TX-маски (set cpu_rst, clear txm_cnt==FF); **por_run НЕ липкий**:
  `por_run <= por_nz`, por_cnt после POR стоит в 00;
- хелперы живы (по 1 МС): `al_cap`, `bus_rd`, `wr_cap`, `cpu_rst`, `por_ce`;
  **cnt<3> ОТСУТСТВУЕТ** (cnt = 3 бита);
- MC **~106/108** (запас ~2 — не впритык); FB-входы ≤ ~200/216;
- НЕТ схлопнутых функций шире ~20 входов, хелперы `__or0000/__D2` на месте;
- GSR не используется, clk = P29/GCK3, входы на местах (INP) — как у POR6;
- если снимать trce: путь clk → tmr_cnt → RST75_r → P75 стал на 2 такта
  длиннее (регистры tick_q/RST75_r) — запас по частоте только вырос;
  критерий анализа 40 нс — по-прежнему не проблема.

Если снова не ляжет — **План Б'** (см. смету выше): снять keep с bus_rd,
затем с por_ce; прислать новый .rpt.

## Критерии успеха (из ANALYSIS.md §6, с поправками)

1. Фит Successful, 0 ERROR; WARNING:897 — 0 (цель).
2. PGND-чек-лист сжался с 9 до 8 ног: P75 = выход (UCF и шапка уже так).
3. Статика (если снимаем trce): путь clk→декод→P75 не хуже 40 нс.
4. Тестбенч ISim: T0..T5 зелёные (квант 51,2 мкс, N тиков, ре-арм, стоп).
5. Железо: баннер идёт, дисплей живой; при N=195 и ISR с делением на 2 —
   счётчик на дисплее тикает 50 раз/с.
