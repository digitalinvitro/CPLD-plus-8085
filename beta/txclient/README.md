# beta/txclient — v3.10 «txclient»: терминальный вывод CPU → PC через захват записи в порт 07h

**Статус:** RTL готов, верифицирован цикл-точной моделью (33/33 PASS, `sim_txclient.py`).
Фит в ISE НЕ выполнялся (нет инструмента в песочнице) — чек-лист фита и план Б ниже.
База: **v3.9.2** (beta/lowsize, фит 10-30 8:32PM: 85/108 МЦ) — всё, кроме TX-тракта,
бит-в-бит v3.9.2.

**ТЗ владельца:** «мы ловим WR и посылаем в UART-TX адрес и данное, которое пишется…
В этом случае нам не нужен TX [транзит] и ты можешь убрать SOD, мы будем знать,
когда процессор пишет в область вывода UART, например по адресу».

## Идея

Передатчик пишет **только то, что процессор пишет в область вывода**. CPLD ловит
запись в порт **07h** и пересылает байт в CH340G своим UART. Адрес на провод не
выносится — ПК знает, что весь поток = вывод терминала. SOD-транзит (CPU
бит-бэнжал SOD → CPLD → CH340, v3.7) удалён; приём (CH340 → CPLD → SID, RIM 20h)
не тронут.

## Протокол

| Операция | Смысл |
|---|---|
| `OUT 07h, A` | символ в терминал ПК (UART 115200 8N1, нога P39 → CH340G.RXD) |
| `IN 07h` | бит 0 = **TXRDY** (1 = окно приёма открыто, запись будет принята); биты 7–1 = 0 |
| `OUT 00h/01h/02h`, `IN 03h` | без изменений (сегменты / разряды+SND / колонки / KBROW) |
| `OUT 04h…06h` | резерв, как в v3.9.2 |

- Декод порта — по **A2–A0** (стиль проекта): алиасы `0Fh, 17h, …` тоже работают.
- Кадр: старт + 8 бит (LSB first) + стоп; **бит = 217 тиков 25 МГц = 8,68 мкс =
  115207,4 бода (+0,006 % к 115200; CH340G на 115200 точен)**.
- `RCONST` — параметр модуля `serial_tx` (216 по умолчанию).

## Контракт прошивки

```asm
; putchar: символ в C — без потерь, темп до ~12,5 тыс. знаков/с
PUTC:   IN    A,(07h)     ; 10T
        RRC               ;  4T   ; бит 0 -> CY
        JC    PUTC_OK     ; 10T/7T
        JP    PUTC        ; ожидание (период опроса 21T = 5,9 мкс)
PUTC_OK:MOV   A,C
        OUT   (07h),A
```

- **Пишешь без опроса — байты теряются** (окно закрыто → строб игнорируется).
  Это документированное поведение, а не дефект.
- TXRDY=1 гарантирует приём: писатель один (CPU), окно непрерывно до загрузки.

## Безопасность по построению (+2 МЦ к голой схеме uart.v)

Маркер `busy` в uart.v падает **на старте бита b7** — перезагрузка, попав в первые
50 % бита b7, портила бы ещё не отобранный приёмником бит (запас съедает
квантование CH340 ±0,2 %). В v3.10 окно приёма

```
tx_acc = !busy & !stop_q & !busy_d          (TXRDY = tx_acc)
stop_q: set — падение busy (начался b7); clear — bittick через бит (начался стоп)
```

открывается **только со старт-бита стопа**: перезагрузка физически не может
попасть в биты данных кадра. Худший случай — срезанный стоп-бит (ресинк приёмника
ПК по новому старту): байты не теряются, возможен FE-флаг, которому
терминалы/pyserial безразличны. Проверено симуляцией: «перезагрузок в бите b7 — 0».

## Почему буфер, а не холд (закрытие вопроса владельца)

К моменту захвата WR# **уже отработал** — HOLD может лишь придержать следующий
доступ; ноль потерь это не даёт, а стоит:

| Вариант | Логика | МЦ (итог) | Замечания |
|---|---|---|---|
| **(б) буфер + TXRDY** (реализован) | serial_tx 19 + окно 2 + строб 0 | **103/108 (95 %)** | прошивка опрашивает TXRDY; ноги HOLD не касается |
| (а) холд CPU на время TX | то же + FSM HOLD/HLDA (триггер HOLD, 2ФФ-синхро, состояния, гейты) | 106…109/108 | на грани непомещения; троттлинг CPU; нога 81 сейчас PGND |

Вердикт: **буфер менее ресурсоёмок в ~1,05–1,1 раза по МЦ и заметно легче по
входам ФБ**, не трогает запаянную в землю ногу HOLD (P81) и при каноническом
putchar даёт те же гарантии без потерь.

## Отличия от v3.9.2

**Удалено** (−3 МЦ): транзит SOD→TX v3.7 (`sod_q`, `tx_pass`, `tx_q`), TX-маска
осталась в истории. Нога **SOD (P72) — снова наблюдатель `(* keep *)`**:
там ВЫХОД CPU, заземлять запрещено.

**Добавлено** (+21 МЦ): `serial_tx` (адаптация uart.v владельца: `send_reg[9:0]`
10, `send_cnt[7:0]` 8, выход `bittick`; маркер busy — схема оригинала),
импульс `tx_send_q` 1, окно приёма `busy_d`+`stop_q` 2. Строб порта 07h —
комбинационный. Чтение 07h подключено в mux KBROW (`{7'b0, TXRDY}`).

## Ресурсы (оценка до фита) и чек-лист

| Метрика | v3.9.2 (факт) | v3.10 (оценка) |
|---|---|---|
| МЦ | 85/108 (79 %) | **103/108 (95 %)** |
| ПТ | 209/540 | ~260–280/540 |
| Триггеры | 54 | 72 |
| Входы ФБ | 180/216 (FB3 исчерпан) | ~190–200/216 |
| Ноги | 72/81 | 72/81 (UCF не меняется) |

Чек-лист фита (п.15 шапки, отличия): **PGND ровно 9** (§11 PORTS_MAP);
**SOD P72 = INP, не в PGND** (выход CPU!); **TX P39 = send_reg_FFd0** (IO-MC,
INIT=1 → idle '1' с включения); SID P73 = RX; state_FSM = ровно 3 триггера;
X1/X2 XOR 4 ПТ; запрещённых литералов нет.

**План Б** (если фит не пройдёт): RCONST=50 → 500 кбод, `send_cnt[5:0]` (−2 МЦ);
выбросить `IN 07h` (mux чтения); в пределе — убрать `stop_q` (−2 МЦ, контракт на
тайминги прошивки вместо конструкции). Запас входов ФБ самый большой в FB4
(18 свободных) — следить в .rpt за распределением.

## ПК-сторона

```sh
stty -F /dev/ttyUSB0 115200 cs8 -cstopb -crtscts raw -echo
cat /dev/ttyUSB0                     # терминал вывода
```

- Всё, что приходит, = вывод CPU (формат без заголовков).
- **Со старой прошивкой fw_mon вывод через SOD пропадёт** (транзит удалён):
  дисплей/клавиатура работают как раньше, обновление прошивки (putchar →
  `OUT 07h`) — отдельная задача в `beta/lowsize/rom`.
- Ввод с ПК (SID, софт-UART прошивки) жив на своей скорости; на одной линии
  полнодуплекс 115200+9600 невозможен — при необходимости сессии ввода
  переключать скорость порта.

## Верификация

```sh
python3 sim_txclient.py        # цикл-точная модель: 33/33 PASS
```

Сценарии: POR/TX='1'/TXRDY; кадр 55h с замером ширин бит (217±2 тика);
поток 18 байт по каноническому putchar (байт-в-байт, стопы целы); структурная
проверка «перезагрузок в бите b7 — 0»; перегрузка (второй байт отброшен);
SOD мёртв; SID=RX; регрессия портов 00/01/02/03; writeback ОЗУ (WE ровно
2 тика, A/D в WB); отброс записи в ПЗУ; RESET в середине кадра (кадр
доигрывается, BREAK нет); алиас 0Fh; кадр при дёргании SOD.

```sh
iverilog -o tb.vvp tb_txclient.v top_txclient_por6_v310_utf8.v && vvp tb.vvp
# ожидание: TOTAL: N pass, 0 fail; SIMULATION PASSED
```

## Источник UART

`serial_tx` — адаптация **uart.v** владельца
(github.com/digitalinvitro/GOWIN, `dumper and microcode/src/uart.v`): RCONST=216,
`send_cnt` сужен до [7:0], async reset убран (INIT достаточен, BREAK невозможен
по построению), добавлен выход `bittick`; маркер busy — схема оригинала.
